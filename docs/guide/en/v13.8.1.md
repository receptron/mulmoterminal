# 13.8.1 — Skill evaluation you can rely on, and its guide

**A snapshot as of 13.8.1 (released 2026-11-26).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

Upgrade:

```bash
npx mulmoterminal@latest
```

Nothing to configure. This is a fix release.

## New features

Nothing new to turn on in the app. The guide gained a page that walks through skill evaluation step
by step — drafting test tasks, measuring, reading the result, improving, adopting and finding the
cheapest model — with what each screen means and what it costs
([#3508](https://github.com/receptron/mulmoterminal/pull/3508)). The issue-to-merge page's screenshots
were retaken from the current screen, and a board card was added
([#3502](https://github.com/receptron/mulmoterminal/pull/3502)).

Read it: [Does a skill help? Measure it](skill-eval.html).

## What looks different

- **The drafting cell talks in your language.** **Draft test tasks** and **Edit the tasks** open a
  Claude cell that now answers in the language the screen is in from its first reply, instead of
  English until you write something ([#3517](https://github.com/receptron/mulmoterminal/pull/3517)).
- **An improvement explains itself in the skill's language** and keeps the rules its tasks do not
  test. Before, it could pass every task by cutting the SKILL.md down and dropping rules nothing
  measured, which adopting would have lost silently
  ([#3510](https://github.com/receptron/mulmoterminal/pull/3510)).
- **The Library's promote, tidy-up and Repeats cells** end their plan with a line asking you to
  approve it with **Yes, manually approve edits**. With the auto-mode option Claude Code lists first,
  a write into `~/.claude` (a memory, a skill, the global `CLAUDE.md`) can be refused; if one still is,
  the cell stops and asks you to switch to manual mode instead of trying another way
  ([#3521](https://github.com/receptron/mulmoterminal/pull/3521)).

More: [Features → Automate & investigate](features.html#3-automate--investigate).

## Under the hood

- **Drafted test tasks always save.** Accepting the drafting cell's plan with the auto-mode option
  could have Claude Code refuse the write into `~/.mulmoterminal/skill-evals/`, leaving nothing saved.
  The cell is now opened with that one folder allowed ahead of time, and the skill saves with its
  file tool ([#3512](https://github.com/receptron/mulmoterminal/pull/3512)). To tell you have it:
  approve a draft with the first option, and the Skills screen shows the saved tasks.
- **Rubric checks are graded by meaning.** A result that says what a check asks in other words now
  passes it, so the runs without the skill are no longer marked down for not using the skill's own
  terms, which overstated "it helps" ([#3516](https://github.com/receptron/mulmoterminal/pull/3516)).
- **An evaluation stops when Claude cannot reach the model.** With an expired login, every attempt used
  to be recorded as failed and the run finished as a measurement, so the mark, the next step and
  **Improve and measure** all read "this skill fails everything". Now it stops, says Claude's message
  as the reason, and does not count ([#3526](https://github.com/receptron/mulmoterminal/pull/3526)).
- **Changing a task's starting files counts as changing the tasks.** Earlier measurements then stop
  counting as measurements of the current tasks, for the next improvement, the mark in the list and
  the next step ([#3495](https://github.com/receptron/mulmoterminal/pull/3495)).
- **On Windows**, checks that a file is still the same file compare its full 64-bit id, so two
  different files can no longer pass for one — restoring a memory from the Trash, a MulmoScript's
  movie or PDF, a shared app's `app.json`, and the trust MulmoTerminal records for a cell's own folder
  ([#3497](https://github.com/receptron/mulmoterminal/pull/3497),
  [#3500](https://github.com/receptron/mulmoterminal/pull/3500)).
- **For contributors:** under `yarn dev`, opening the backend's port (34567) now redirects to the
  Vite port (6856) instead of serving whatever old build was left in `dist/`
  ([#3501](https://github.com/receptron/mulmoterminal/pull/3501)). Test fixes for specs that failed now
  and then ([#3494](https://github.com/receptron/mulmoterminal/pull/3494),
  [#3505](https://github.com/receptron/mulmoterminal/pull/3505),
  [#3492](https://github.com/receptron/mulmoterminal/pull/3492)). Nothing to do.
