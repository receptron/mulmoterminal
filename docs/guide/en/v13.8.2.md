# 13.8.2 — A conversation moved to the background stays in view

**A snapshot as of 13.8.2 (released 2026-11-26).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

Upgrade:

```bash
npx mulmoterminal@latest
```

Nothing to configure. This is a fix release.

## New features

Nothing new to turn on. This release fixes what is already there.

## What looks different

- **The skill evaluation says whether an improvement is really better.** The improvement's panel used
  to show "now X → improvement Y" and point at **Adopt** whenever Y was higher. It now compares the two
  by the same rule the summary uses, and says in a sentence whether it passes more often, less often,
  or by no more than the runs vary — or that there are too few runs to compare. It names the tasks the
  improvement passed less often, and the next step points at Adopt only when it passes more often.
  **Adopt** itself is still there
  ([#3531](https://github.com/receptron/mulmoterminal/pull/3531)).
- **Tasks that pass with and without the skill are named.** A task that passes every time either way
  cannot show what the skill does. The result lists those tasks, the per-task table marks them
  *(passes either way)*, and drafting now asks for tasks an agent without the skill is likely to get
  wrong ([#3532](https://github.com/receptron/mulmoterminal/pull/3532)).
- **The HTML plan skill asks for Canvas when it is off.** In a project cell where Canvas is not
  switched on, `mulmoterminal-html-plan` stops before drafting and tells you to switch Canvas on for
  the folder in the launcher's MCP toggles and then choose **Restart the agent** in the cell's menu.
  It no longer tries a workaround that would leave the page out of the pane
  ([#3542](https://github.com/receptron/mulmoterminal/pull/3542)).

More: [Does a skill help? Measure it](skill-eval.html#result) and
[Features](features.html).

## Under the hood

- **A Claude conversation moved to the background with ← stays in view.** Claude Code continues it
  under a new session id. The cell's activity history and conversation pane used to stop at the
  moment ← was pressed, while the terminal itself went on. They now follow the new id, and reopening
  the cell later resumes it too ([#3540](https://github.com/receptron/mulmoterminal/pull/3540)). To
  tell you have it: press ←, give one more instruction, and the conversation pane shows that turn.
  See [FAQ — a cell I reopened came back without my latest conversation](faq.html#cell-reopened).
- **The prompts pane is not thrown off by Claude Code's spare process.** Pressing ← also starts a
  spare Claude Code process in the background, and its startup message could make the prompts pane
  read an unrelated conversation for a moment
  ([#3545](https://github.com/receptron/mulmoterminal/pull/3545)). Nothing to do.
- **A skill call no longer splits a turn.** After a Skill tool call, Claude Code writes the skill's
  text into the conversation as if you had typed it, and a pasted image adds a note the same way. The
  conversation view showed that as a new prompt, the header took it as your latest prompt, and the
  turn's tool list came out empty. These are now read as part of the turn they belong to
  ([#3550](https://github.com/receptron/mulmoterminal/pull/3550)). To tell you have it: run a skill,
  and the conversation view shows one turn with your prompt and the skill's tools.
- **For contributors:** code the duplicate scanner flagged now lives in one place each — the
  last-turn readers of copilot, Antigravity and Grok, the tool-call rows of the transcript views, two
  Library routes and the Library's back button
  ([#3548](https://github.com/receptron/mulmoterminal/pull/3548)). Nothing to do.
