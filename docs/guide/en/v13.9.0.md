# 13.9.0 — Your own git commands no longer collide with MulmoTerminal

**A snapshot as of 13.9.0 (released 2026-11-27).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

Upgrade:

```bash
npx mulmoterminal@latest
```

Nothing to configure.

## New features

Nothing new to turn on in this release.

## What looks different

- **The What's new dialog says thank you.** The dialog that opens after an upgrade now opens with
  "MulmoTerminal 13.9.0 is out!" and adds a short note under it: thanks for using MulmoTerminal, and
  if it helps you, tell a friend or a colleague, or write a post about it
  ([#3566](https://github.com/receptron/mulmoterminal/pull/3566)). You are probably reading this page
  in that dialog right now.

## Under the hood

- **Your own git commands no longer fail with `index.lock: File exists`.** MulmoTerminal checks each
  open folder's git status in the background (the uncommitted-changes count, the Files tree's
  colours). That check could briefly hold `.git/index.lock`, and a `git add`, `git commit`,
  `git switch` or `git merge` you or an agent ran at the same moment failed with
  `fatal: Unable to create '…/.git/index.lock': File exists`, even though the lock was gone a second
  later. The background checks now never take that lock
  ([#3564](https://github.com/receptron/mulmoterminal/pull/3564), for
  [#3556](https://github.com/receptron/mulmoterminal/issues/3556)). Nothing to do. To tell you have
  it: scripts that commit and then immediately `git add` or `git switch` in a folder open in a cell
  stop failing now and then.
- **The Files tree opens to a file you clicked in the terminal.** Clicking a path in a cell's output
  while the Files pane was closed opened the file, but the tree stayed folded, so you could not see
  where the file lives. The tree now opens the folders down to it and scrolls to it
  ([#3563](https://github.com/receptron/mulmoterminal/pull/3563)). To tell you have it: close the
  Files pane, click a file path in a cell, and the tree is open down to that file. More:
  [Features](features.html).
- **An Antigravity plan approval starts its own turn.** When you approve a plan in Antigravity's own
  window, the conversation view used to fold all the work after it into the turn that asked for the
  plan, and the finished-turn notice had no prompt. The approval now starts a new turn of its own
  ([#3560](https://github.com/receptron/mulmoterminal/pull/3560)). More:
  [Agents](agents.html#at-a-glance).
- **Older pages of a Claude conversation split into turns correctly.** 13.8.2 stopped a skill call
  from splitting a turn. The same mix-up could still happen when the conversation view loaded an
  older page, or when the header read your latest prompt, if that read began right at a skill's text.
  It no longer does ([#3554](https://github.com/receptron/mulmoterminal/pull/3554)). Nothing to do.
