# 12.2.0 — Solid models for parts that are made

**A snapshot as of 12.2.0 (released 2026-11-17).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

Upgrade:

```bash
npx mulmoterminal@latest
```

## New features

### presentBrep: a solid model you can send to a CAD program or a printer

Ask an agent for a part — "a bracket with two 5 mm holes and rounded corners", "a box lid that
fits this box" — and it can now answer with a **solid model** in the Canvas
([#3297](https://github.com/receptron/mulmoterminal/pull/3297)). The card shows the part in 3D, a
check report from the build, and a download button for each file:

- **STEP** — opens as a solid in a CAD program (Fusion, FreeCAD, Onshape …)
- **STL** — for a 3D printer's slicer
- **Drawings** — a sheet of line drawings from several sides
- **The script** — the replicad script the agent wrote, to rebuild or change

The files are also saved under `artifacts/brep/` in the workspace.

How it differs from ShapeScript, which is still there: ShapeScript is for models you **look at**.
`presentBrep` is for parts that are **made** or must **fit** — exact curved surfaces, rounded or
cut edges where you ask for them, and a file a CAD program treats as a real solid.

**To try it:** make sure the cell has the Canvas tools on (the workspace has them), and ask for a
part. No setting is needed.

**One thing to know before you use it.** The model is built from a script the agent writes, and
MulmoTerminal runs that script inside its own server process **without asking you first** and
without the agent's sandbox. That was a deliberate choice, because a part is usually built, checked
and rebuilt several times. So turn the Canvas tools on only for cells where you already let the
agent run code on your machine. While a part is being built (from a fraction of a second to a
couple of seconds) the server answers nothing else; the first build also loads the geometry
engine, which takes a moment once.

More on the Canvas tools: [Features](features.html).

## What looks different

- **Claude Code 2.1.326 no longer stops a new cell to ask** *"Adding a new directory: …/mulmoterminal-drops/… Is this a directory you created or one you trust?"*
  ([#3315](https://github.com/receptron/mulmoterminal/pull/3315), for
  [#3313](https://github.com/receptron/mulmoterminal/issues/3313)). That folder is where files you
  drop or paste into a cell are kept for the agent to read. MulmoTerminal now records it as trusted
  in Claude Code's own config (`~/.claude.json`, or the account's config when the cell uses
  another login). Cells that are already open keep their state; the change applies to cells started
  after the upgrade.
- **A picture, PDF, video or sound behind a symlink to a folder outside the project shows in the
  Files pane** instead of *"path escapes the project root"*
  ([#3302](https://github.com/receptron/mulmoterminal/pull/3302)). A text file reached that way
  says why it is not shown, in your UI language.
- **A slow request says it timed out** — that the server did not answer within the time limit,
  that it may be busy, and to restart MulmoTerminal if it keeps happening — instead of the
  browser's *"signal is aborted without reason"*
  ([#3294](https://github.com/receptron/mulmoterminal/pull/3294)).

## Under the hood

### File operations check again after they act

Every file operation checked that a path stayed inside the project, then acted on the path by
name. If a folder on that path was swapped for a link to somewhere outside in between, the
operation acted outside. Each one now checks again on what it actually touched, and refuses if it
is not inside: writes and reads in the Files pane, new files and folders, rename and Trash, folder
listings and previews, the plugins' own file access, and HTML pages under `artifacts/html`
([#3307](https://github.com/receptron/mulmoterminal/pull/3307),
[#3308](https://github.com/receptron/mulmoterminal/pull/3308),
[#3311](https://github.com/receptron/mulmoterminal/pull/3311),
[#3312](https://github.com/receptron/mulmoterminal/pull/3312),
[#3314](https://github.com/receptron/mulmoterminal/pull/3314),
[#3316](https://github.com/receptron/mulmoterminal/pull/3316),
[#3317](https://github.com/receptron/mulmoterminal/pull/3317),
[#3318](https://github.com/receptron/mulmoterminal/pull/3318)).
Separately, a link inside the project to an outside file that did not exist yet no longer counts
as inside, so saving through it cannot create a file outside
([#3304](https://github.com/receptron/mulmoterminal/pull/3304)). Nothing to do; ordinary files and
links that stay inside behave as before.

### Pasting after a reconnect in copy-mode

If the page reloaded or reconnected while a pane was scrolled back (tmux copy-mode), the first
paste after "Back to input" could lose its first line or not arrive at all. Fixed
([#3309](https://github.com/receptron/mulmoterminal/pull/3309)).

### A cell closed from outside closes

A cell closed through the close route (for example by another tool) stayed on screen as
*"[session ended — exit 1]"*. It closes again
([#3305](https://github.com/receptron/mulmoterminal/pull/3305)).

### Dependencies

Patch and minor updates ([#3298](https://github.com/receptron/mulmoterminal/pull/3298)).

**How to tell you have the release:** open a new claude cell with Claude Code 2.1.326 or later —
the trust question above does not appear — and ask an agent for a simple part with `presentBrep`;
the card has STEP and STL buttons.
