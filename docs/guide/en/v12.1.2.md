# 12.1.2 — Token rotation stops choosing a subscription that cannot run Claude Code

**A snapshot as of 12.1.2 (released 2026-11-10).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

**Nothing to configure.** Upgrade and the fix is there:

```bash
npx mulmoterminal@latest
```

## New features

None in this release.

## What looks different

Nothing on screen moved. What changed is which subscription a new cell starts on.

## Under the hood

### Token rotation skips a subscription that cannot run Claude Code

With [token rotation](token-rotation.html) on, MulmoTerminal checks each subscription's usage in the
background and starts each new Claude session on the one with the most room. A subscription whose
organization has turned off Claude Code access cannot answer that check — Claude Code replies
*"Your organization has disabled Claude subscription access for Claude Code"* — so its last good
reading stayed on file. When that old reading said the week was almost unused, rotation chose that
subscription for **every** new session, and none of them could work.

Two things changed ([#3292](https://github.com/receptron/mulmoterminal/pull/3292), for
[#3291](https://github.com/receptron/mulmoterminal/issues/3291)):

- **That reply is recognised**, and the subscription is left out of rotation entirely while it
  stands. Once access is turned on again, the next usage check succeeds and it comes back by itself.
- **A reading the latest check could not confirm no longer wins.** A subscription whose last usage
  check failed, for any reason, is now tried only after every subscription with a fresh reading.

Right after the server starts, the first check of each subscription has not run yet, so for about a
minute and a half a new cell can still land on such a subscription.

**How to tell you have the fix:** open the token usage view. The subscription with access turned off
shows no figures, and new cells (and their account mark) name a different subscription.

### Image generation keeps calling the Gemini API version it was built for

The Google client library this release ships with changed its default from the `v1beta` API to
`v1`. Image generation uses a preview model and image settings that were only ever tested on
`v1beta`, so the client is now pinned to `v1beta`
([#3288](https://github.com/receptron/mulmoterminal/pull/3288)). Nothing to do; image generation
behaves as before.

### Dependencies and docs

Dependencies were updated, including the `@mulmoclaude/*` plugins to their new majors and
`@google/genai` 3 ([#3286](https://github.com/receptron/mulmoterminal/pull/3286),
[#3290](https://github.com/receptron/mulmoterminal/pull/3290)). The
[Alternatives](alternatives.html) page now lists T3 Code
([#3289](https://github.com/receptron/mulmoterminal/pull/3289)).
