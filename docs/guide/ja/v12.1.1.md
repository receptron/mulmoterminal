# 12.1.1 — Codex のセルが作業中かどうかを示し続ける

**12.1.1 時点（2026-11-06 リリース）のスナップショットです。** アプリが変わるにつれて古くなります。
それは想定どおりで、最新の説明は各節からリンクしているガイドにあります。

**設定は要りません。** 上げれば直ります:

```bash
npx mulmoterminal@latest
```

## 新機能

この版にはありません。

## 画面の変化

### Codex のセルの作業中の点と完了の知らせが、止まったままにならない

Codex を動かしているセルは、Codex が作業しているあいだ作業中の点を出し、ターンが終わると知らせます
（完了の音と、設定していればスマホへの通知）。そのためには MulmoTerminal が Codex の書く会話ファイルを
見つける必要があり、次の 2 つの場合には見つけられず、セルはずっと何もしていないように見えていました。

- **セルを開いてから 30 分以上経って最初のプロンプトを送ったとき。** Codex は最初のプロンプトを
  送った時点で初めてファイルを作りますが、探すのを 30 分で打ち切っていました。いまはセルが開いている
  あいだ探し続けます（[#3284](https://github.com/receptron/mulmoterminal/pull/3284)、
  [#3282](https://github.com/receptron/mulmoterminal/issues/3282) の対応）。
- **そのようなセルが動いたまま、サーバーを再起動したとき。** 再起動後、MulmoTerminal はセルで動き
  続けている Codex につなぎ直しますが、どのファイルがそのセルのものかという記録が無いと、見つけ直せ
  ませんでした。いまは動いている Codex に、開いている会話ファイルを尋ね、それが 1 つに決まるときだけ
  結び付けます。ほかのセルの会話を取り違えることはありません
  （[#3285](https://github.com/receptron/mulmoterminal/pull/3285)、
  [#3283](https://github.com/receptron/mulmoterminal/issues/3283) の対応）。再起動の前に終わっていた
  ターンを、もう一度知らせることもありません。macOS と Linux で動きます（どちらにもある `lsof` を
  使います）。

すでにこの状態になっているセルも、Codex が動き続けていれば、更新後に初めてサーバーを起動したときに
拾い直されます。

**修正が入ったかどうかの見分け方:** 作業中の表示が止まっていた Codex のセルで、プロンプトを送ります。
12.1.1 からは、Codex が答えているあいだ点が作業中になり、終わると完了の知らせが来ます。
詳しく: [複数のエージェントを混在させる](basics.html#claude-and-codex)

## 見えない変化

この版にはほかにありません。
