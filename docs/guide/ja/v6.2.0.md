# 6.2.0 — Codex セルが承認待ちを知らせるように

**6.2.0（2026-09-25 リリース）時点のスナップショットです。** アプリが進めば古くなります。それは
想定どおりで、最新の説明は各節からリンクしているガイドにあります。

設定は要りません。最初に Codex セルを開いたときに、一度だけ答える質問があります。

## Codex の承認プロンプトが「入力が必要」になる

これまで Codex のセルは、Codex が自分の承認プロンプト（「Would you like to run the following
command?」）で止まっている間も**処理中**のままでした。何時間待っていても、知らせる手段がありませんでした。

これからは、そのプロンプトが出るとセルが**入力が必要**になります。Claude の許可プロンプトとまったく
同じ扱いで、見ていないセルには注目マークが付き、音が鳴り、スマホ通知を有効にしていれば **Waiting for you** の
通知が届きます。プロンプトに答えてターンが終われば、いつもどおり次の状態に移ります。

**やることは一つだけ。** アップグレード後に最初に開いた Codex セルのターミナルに、次の表示が出ます。

```text
  Hooks need review
  1 hook is new or changed.
  Hooks can run outside the sandbox after you trust them.
› 1. Review hooks
  2. Trust all and continue
  3. Continue without trusting (hooks won't run)
```

この hook は MulmoTerminal のものです。**2. Trust all and continue** を選んでください（中身を先に
見たいなら **1**）。承認プロンプトの内容を、このマシンの MulmoTerminal に送るだけのものです。
Codex はこの答えを `~/.codex/config.toml` に覚えます。hook はどのセルでも同じ内容なので、以後の
セル、別のプロジェクト、別のポートでは聞かれません。**3** を選ぶと 6.1.0 と同じ動きのままです。

**効いているかの確かめ方。** Codex セルを開いて承認が要る作業（たとえばプロジェクトの外にファイルを
書く）を頼み、別のセルをクリックしておきます。プロンプトが出た時点で、Codex セルが**入力が必要**に
なります。

**対象外のもの。**

- MulmoTerminal がプロンプトを入力した状態で始める Codex セッション（コレクションのアクションや
  バックグラウンドチャット）には hook を付けません。上の一度きりの質問が、その入力を横取りして
  しまうためです。こうしたセッションが承認プロンプトで止まっても、音は鳴りません。
- Windows では、まだ hook を登録していません。
- 動作は Codex CLI 0.156.1 で確認しています。

各エージェントが何を知らせるか：[どの coding agent を使うか](agents.html#at-a-glance)。
スマホに届くタイミング：[スマホ通知](notifications.html#kinds)。

## 修正：`http_proxy` の下でも状態が届く

`http_proxy` または `ALL_PROXY` を設定した状態で MulmoTerminal を起動していると（`NO_PROXY` に
`localhost` が入っていない場合）、Claude の hook が報告を MulmoTerminal ではなくプロキシへ送って
いました。そのため Claude のセルが処理中にも完了にもならず、プロンプトの文面がプロキシに渡って
いました。レート制限の読み取り、Copilot の hook、MulmoTerminal 同梱スキルの curl コマンドも同じ
でした。いまはどれも、プロキシの設定に関係なく MulmoTerminal に直接届きます。

**直っているかの確かめ方。** 設定は要りません。プロキシの変数を設定したままでも、Claude セルに
プロンプトを送ると状態の表示が動きます。
