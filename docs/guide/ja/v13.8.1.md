# 13.8.1 — 頼れるスキルの評価と、その使い方のガイド

**13.8.1（2026-11-26 リリース）時点のスナップショットです。** アプリが進むにつれて古くなります。
それは想定どおりで、最新の内容は各節からリンクしているガイドにあります。

更新:

```bash
npx mulmoterminal@latest
```

設定は要りません。直しのリリースです。

## 新機能

アプリに新しく入れるものはありません。ガイドに、スキルの評価を順を追って説明するページが増えました。
課題を作る、測る、結果を読む、改善案を作る、採用する、安いモデルを探す、の各画面の意味と費用を書いて
あります（[#3508](https://github.com/receptron/mulmoterminal/pull/3508)）。issue から merge までの
ページの画面写真は今の画面から撮り直し、ボードのカードの写真も足しました
（[#3502](https://github.com/receptron/mulmoterminal/pull/3502)）。

読む: [スキルは効いているか](skill-eval.html)

## 画面の変化

- **課題を作るセルが、画面の言語で話します。** **評価の課題を作る** と **課題を直す** で開く Claude の
  セルは、最初の返事から画面の言語で答えるようになりました。これまでは、こちらが何か書くまで英語でした
  （[#3517](https://github.com/receptron/mulmoterminal/pull/3517)）。
- **改善案は、スキルの言語で説明し**、課題で試していない決まりを残します。これまでは、SKILL.md を削って
  どの課題にも出てこない決まりを落とし、全部の課題に通ることがあり、採用するとそれが黙って消える
  ところでした（[#3510](https://github.com/receptron/mulmoterminal/pull/3510)）。
- **ライブラリの昇格・整理・繰り返しのセル** は、プランの最後に「**Yes, manually approve edits** で承認して」
  と一行添えます。Claude Code が最初に出す auto mode の選択肢では、`~/.claude` の下への書き込み（記憶・
  スキル・全体の `CLAUDE.md`）が断られることがあります。それでも断られたら、セルは別の手で書こうとせず、
  止まって manual mode に切り替えるよう頼みます（[#3521](https://github.com/receptron/mulmoterminal/pull/3521)）。

詳しく: [機能一覧](features.html)

## 見えない変化

- **作った課題が必ず保存されます。** 課題を作るセルのプランを auto mode の選択肢で承認すると、
  `~/.mulmoterminal/skill-evals/` への書き込みを Claude Code が断り、何も保存されないことがありました。
  セルを開くときにそのフォルダ一つだけを前もって許し、スキルはファイルを書く道具で保存するように
  しました（[#3512](https://github.com/receptron/mulmoterminal/pull/3512)）。入ったかどうかは、案を
  最初の選択肢で承認すると、Skills の画面に保存された課題が出ることでわかります。
- **点検項目を意味で採点します。** 点検項目が求めることを別の言葉で書いた結果も合格になり、スキルなしの
  回がスキルの用語を使わないだけで落とされることがなくなりました。これまでは「効いている」を大きく
  見せていました（[#3516](https://github.com/receptron/mulmoterminal/pull/3516)）。
- **Claude がモデルに届かないときは、評価を止めます。** ログインが切れていると、これまではすべての回を
  失敗として記録し、測定として終わっていたので、一覧の印、次の一手、**改善案を作って測る** がそろって
  「このスキルは全部落ちる」と読んでいました。今は止まり、Claude の言葉を理由として出し、測定として
  数えません（[#3526](https://github.com/receptron/mulmoterminal/pull/3526)）。
- **課題の始めのファイルを変えると、課題が変わったとみなします。** 前の測定は、次の改善案、一覧の印、
  次の一手のための今の課題の測定として数えなくなります（[#3495](https://github.com/receptron/mulmoterminal/pull/3495)）。
- **Windows** で、ファイルが同じファイルのままかを確かめるときに 64 ビットの識別子をそのまま比べるように
  なり、別のファイルを同じものと取り違えなくなりました。ごみ箱からの記憶の復元、MulmoScript の動画や PDF、
  共有アプリの `app.json`、セル自身のフォルダの信頼の記録が対象です
  （[#3497](https://github.com/receptron/mulmoterminal/pull/3497)、
  [#3500](https://github.com/receptron/mulmoterminal/pull/3500)）。
- **開発する人向け:** `yarn dev` のとき、バックエンドの port（34567）を開くと、`dist/` に残った古いビルドを
  配る代わりに Vite の port（6856）へ移ります（[#3501](https://github.com/receptron/mulmoterminal/pull/3501)）。
  ときどき落ちていたテストの直し（[#3494](https://github.com/receptron/mulmoterminal/pull/3494)、
  [#3505](https://github.com/receptron/mulmoterminal/pull/3505)、
  [#3492](https://github.com/receptron/mulmoterminal/pull/3492)）。することはありません。
