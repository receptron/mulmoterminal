# 12.1.2 — トークンローテーションが Claude Code を使えない契約を選ばなくなる

**12.1.2 時点（2026-11-10 リリース）のスナップショットです。** アプリが変わるにつれて古くなります。
それは想定どおりで、最新の説明は各節からリンクしているガイドにあります。

**設定は要りません。** 上げれば直ります:

```bash
npx mulmoterminal@latest
```

## 新機能

このリリースにはありません。

## 画面の変化

画面の見た目は変わりません。変わったのは、新しいセルがどの契約で始まるかです。

## 見えない変化

### Claude Code を使えない契約をトークンローテーションが飛ばす

[トークンローテーション](token-rotation.html)を使っていると、MulmoTerminal は裏で各契約の使用量を確かめ、
新しい Claude のセッションをいちばん余裕のある契約で始めます。組織が Claude Code での利用を止めている契約は、
この確認に答えられません（Claude Code は *「Your organization has disabled Claude subscription access for Claude Code」*
と返します）。そのため、最後にうまく取れた使用量がそのまま残っていました。その古い値が「今週ほとんど使っていない」と
言っていると、ローテーションは **すべての** 新しいセッションをその契約で始め、どれも動きませんでした。

変わったのは二つです（[#3292](https://github.com/receptron/mulmoterminal/pull/3292)、
[#3291](https://github.com/receptron/mulmoterminal/issues/3291) の修正）:

- **この返事を見分けて**、そう言われている間はその契約をローテーションから外します。利用が再び許可されれば、
  次の使用量の確認が通り、自然に戻ってきます。
- **最新の確認で確かめられなかった使用量では選ばなくなりました。** 最後の確認に失敗した契約は、理由にかかわらず、
  新しい使用量が取れているどの契約よりも後に回します。

サーバーを起動した直後は、各契約の最初の確認がまだ済んでいないので、1 分半ほどは新しいセルがそういう契約に
割り当てられることがあります。

**修正が入ったかどうかの見分け方:** トークンの使用量の画面を開くと、利用を止められている契約には数字が出ていません。
新しいセル（とその契約の表示）は、別の契約の名前になっています。

### 画像生成が、作られたときの Gemini API の版を呼び続ける

このリリースに入っている Google のライブラリは、既定の API を `v1beta` から `v1` に変えました。画像生成は
プレビュー版のモデルと画像用の設定を使っていて、確かめてあるのは `v1beta` だけなので、`v1beta` を明示して
固定しました（[#3288](https://github.com/receptron/mulmoterminal/pull/3288)）。何もしなくて大丈夫です。
画像生成はこれまでどおり動きます。

### 依存関係とドキュメント

依存関係を更新しました。`@mulmoclaude/*` のプラグインを新しいメジャー版に、`@google/genai` を 3 に上げています
（[#3286](https://github.com/receptron/mulmoterminal/pull/3286)、
[#3290](https://github.com/receptron/mulmoterminal/pull/3290)）。[ほかの選択肢](alternatives.html)のページに
T3 Code を加えました（[#3289](https://github.com/receptron/mulmoterminal/pull/3289)）。
