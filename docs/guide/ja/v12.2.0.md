# 12.2.0 — 作る部品のソリッドモデル

**12.2.0 時点（2026-11-17 リリース）のスナップショットです。** アプリが変わるにつれて古くなります。
それは想定どおりで、最新の説明は各節からリンクしているガイドにあります。

上げ方:

```bash
npx mulmoterminal@latest
```

## 新機能

### presentBrep: CAD や 3D プリンタに渡せるソリッドモデル

エージェントに部品を頼むと（「5 mm の穴が二つあって角の丸いブラケット」「この箱に合うふた」）、
Canvas に **ソリッドモデル** で答えられるようになりました
（[#3297](https://github.com/receptron/mulmoterminal/pull/3297)）。カードには部品の 3D 表示、組み立て時の
検査の報告、ファイルごとのダウンロードボタンが並びます:

- **STEP** — CAD（Fusion、FreeCAD、Onshape など）でソリッドとして開けます
- **STL** — 3D プリンタのスライサー用
- **図面** — 何方向かから見た線画を一枚にしたもの
- **スクリプト** — エージェントが書いた replicad のスクリプト。作り直しや手直しに使えます

ファイルはワークスペースの `artifacts/brep/` にも保存されます。

これまでの ShapeScript との違い（ShapeScript もそのまま使えます）: ShapeScript は **見る** ためのモデル、
`presentBrep` は **作る**・**はめ合わせる** ための部品です。正確な曲面、指定した辺の丸めや面取り、
CAD が本物のソリッドとして扱えるファイルが出ます。

**試し方:** セルで Canvas のツールが使えること（ワークスペースは使えます）を確かめて、部品を頼むだけです。
設定は要りません。

**使う前に知っておくこと。** モデルはエージェントが書いたスクリプトから組まれ、MulmoTerminal はそのスクリプトを
自分のサーバーの中で **確認なしに**、エージェントのサンドボックスの外で動かします。部品は組んで、確かめて、
何度も組み直すものなので、あえてそうしています。ですから Canvas のツールは、もともとエージェントにこのマシンで
コードを動かさせているセルでだけ使ってください。部品を組んでいる間（一瞬から数秒）はサーバーがほかに応答しません。
最初の一回は形状エンジンを読み込むので、少し待ちます。

Canvas のツールについて詳しくは: [機能](features.html)。

## 画面の変化

- **Claude Code 2.1.326 が、新しいセルを止めて**
  *「Adding a new directory: …/mulmoterminal-drops/… Is this a directory you created or one you trust?」*
  **と聞かなくなりました**（[#3315](https://github.com/receptron/mulmoterminal/pull/3315)、
  [#3313](https://github.com/receptron/mulmoterminal/issues/3313) の修正）。このフォルダは、セルにドロップしたり
  貼り付けたりしたファイルをエージェントが読めるように置いておく場所です。MulmoTerminal が Claude Code 自身の
  設定（`~/.claude.json`、別のログインを使うセルではそのアカウントの設定）に信頼済みとして書くようにしました。
  開いたままのセルはそのままで、上げたあとに起動したセルから効きます。
- **プロジェクトの外のフォルダへのシンボリックリンクの先にある画像・PDF・動画・音声が、Files ペインに表示されます。**
  これまでは *「path escapes the project root」* と出るだけでした
  （[#3302](https://github.com/receptron/mulmoterminal/pull/3302)）。同じ形のテキストファイルは、
  表示しない理由を画面の言語で伝えます。
- **応答の遅いリクエストが、時間切れだと伝えます。** サーバーが制限時間内に答えなかったこと、混み合っているかもしれないこと、
  繰り返すなら MulmoTerminal を再起動することを伝えます。これまではブラウザの *「signal is aborted without reason」*
  でした（[#3294](https://github.com/receptron/mulmoterminal/pull/3294)）。

## 見えない変化

### ファイル操作が、動いたあとにもう一度確かめる

これまでのファイル操作は、パスがプロジェクトの中にあることを確かめてから、名前でそのパスを扱っていました。
その間にパスの途中のフォルダが外へのリンクにすり替えられると、操作は外で行われていました。
いまは、実際に触ったものをもう一度確かめ、中になければ断ります。対象は Files ペインの読み書き、
新しいファイルとフォルダ、名前の変更とゴミ箱、フォルダの一覧とプレビュー、プラグインのファイル操作、
`artifacts/html` の HTML ページです
（[#3307](https://github.com/receptron/mulmoterminal/pull/3307)、
[#3308](https://github.com/receptron/mulmoterminal/pull/3308)、
[#3311](https://github.com/receptron/mulmoterminal/pull/3311)、
[#3312](https://github.com/receptron/mulmoterminal/pull/3312)、
[#3314](https://github.com/receptron/mulmoterminal/pull/3314)、
[#3316](https://github.com/receptron/mulmoterminal/pull/3316)、
[#3317](https://github.com/receptron/mulmoterminal/pull/3317)、
[#3318](https://github.com/receptron/mulmoterminal/pull/3318)）。
また、プロジェクトの中にある「外のまだ無いファイルへのリンク」を中とみなさなくなったので、
そこへ保存して外にファイルを作ることもできなくなりました
（[#3304](https://github.com/receptron/mulmoterminal/pull/3304)）。何もしなくて大丈夫です。
ふつうのファイルや、中を指すリンクはこれまでどおり動きます。

### コピーモード中の再接続のあとの貼り付け

ペインをさかのぼって見ている間（tmux のコピーモード）にページの再読み込みや再接続が起きると、
「Back to input」のあとの最初の貼り付けで、一行目が消えたり、何も届かなかったりしました。直りました
（[#3309](https://github.com/receptron/mulmoterminal/pull/3309)）。

### 外から閉じたセルが閉じる

閉じるための API で（たとえば別のツールから）閉じたセルが、*「[session ended — exit 1]」* と出たまま
残っていました。また閉じるようになりました（[#3305](https://github.com/receptron/mulmoterminal/pull/3305)）。

### 依存関係

パッチ版・マイナー版を更新しました（[#3298](https://github.com/receptron/mulmoterminal/pull/3298)）。

**上がったかどうかの見分け方:** Claude Code 2.1.326 以降で新しい claude セルを開くと、上の信頼の確認が出ません。
エージェントに `presentBrep` で簡単な部品を頼むと、カードに STEP と STL のボタンがあります。
