# issue をエージェントに渡して merge まで
{: .no_toc }

GitHub の issue を名指しすると、エージェントが merge まで進めます。issue を読み、issue に書かれていない
ことだけをあなたに聞き、issue のブランチで実装して PR を出します。それを **別のセッションの別の
エージェント** が一往復ずつレビューし、見つかったものを直し、リポジトリの merge の条件を満たしたら
merge します。いくつも名指しすれば、それぞれが専用のワークツリーとセルで並んで進みます。

あなたが受け持つのは二つです。**決まりごと**（誰がレビューするか、LGTM がいくつ要るか。リポジトリに
一度書くだけ）と、**質問への答え**（決めることがあるエージェントは、自分のセルであなたに聞きます）。
往復、数え、片付けは MulmoTerminal が回します。

## 何が起きるか {#what-happens}

三種類のセッションが関わり、どれも見えるセルとして動きます。

| 役 | すること | 動く場所 |
|---|---|---|
| **まとめ役**（いくつも渡すときだけ） | issue ごとに実装役を起動し、待ちの列を持ち、一つ終わるたびに次を始め、人が要るときに知らせます。自分では実装も merge もしません。 | コマンドを打ったワークスペースのセル |
| **実装役**（作者） | issue を読み、決まっていないことを聞き、実装し、PR を出し、レビューの往復を回し、直し、merge します。 | 自分のセル。issue 専用の [worktree](worktree.html) |
| **レビュー役** | 一往復ずつレビューし、判定を PR に書き込みます。編集も merge もしません。 | 自分のセル。`~/.mulmoterminal/review-worktrees/` に PR の最新の push を取り出したワークツリー（作者のチェックアウトには触れません） |

issue 一つの流れ:

```
issue ──▶ 実装役: 質問 → 実装 → PR
                │
                ▼
        requestReview ──▶ レビュー役: 一往復 → PR に REVIEW VERDICT
                ▲                         │
                │ CHANGES REQUESTED       │ 最新の push に LGTM + CI 合格
                └──── 直して push ◀──────┤
                                          ▼
                                実装役が merge → MulmoTerminal がレビュー役、
                                実装役、そのワークツリーを閉じる
```

**数えるのはエージェントではなく MulmoTerminal です。** 往復ごとに依頼をレビュー役に送り、判定の行を
読み戻し、PR の最新の push と CI を読み直して、結果を作者に打ち込みます。merge の条件を満たしたかも
そこに含まれます。エージェントが往復の上限を言いくるめて超えたり、古い push への LGTM を数えたりは
できません。

## 始める前に {#setup}

### 1. リポジトリのレビューのしかたを書く

リポジトリのクローンの直下にある `.mulmoterminal.json` に、`review` のキーを書きます。これが無いと
レビューは始まりません。

```json
{ "review": {} }
```

これですべて既定になります。レビュー役は **codex**、往復は最大 **10** 回、最新の push に **1** つの
LGTM（と CI の全件合格）で merge できる状態になり、レビュー役は同梱の `mulmoterminal-review` スキルに
従います。変えるときは:

```json
{ "review": { "reviewer": "claude", "maxRounds": 5, "requiredLgtm": 2 } }
```

値が一つでもおかしいと（このアプリが動かさないエージェント、範囲外の数、綴りの違うキー）、勝手に
レビュー役を決めずに **キーごと無視** します。**設定 → ディレクトリ設定** で確かめられます。正しければ
**Review** の行が出て、壊れていれば *ignored* に並びます。
各項目 → [このリポジトリの PR のレビューのしかた](config.html#dir-review)

### 2. ワークスペースのセルから実行する

使う道具（`requestReview`、`startIssueSession` など）は、MulmoTerminal の道具を全部持つセッションにだけ
渡されます。[ワークスペース](glossary.html#workspace) のセルで動く **Claude、Codex、Copilot** です。
プロジェクトのディレクトリのセルには無く、スキルはそう言って止まります。クローンはどこにあっても
構いません。エージェントが見つけます。

### 3. `gh` にログインしておく

実装役は `gh` と `git` で issue を読み、push し、PR を出します。レビュー役は `gh` で PR を読み、
コメントします。ターミナルで一度 `gh auth status` を打ち、ログインしていなければ `gh auth login` します。

### 4. （任意）同時に動かす数

実装役は、このマシンのすべてのリポジトリを合わせて、同時に **2** つまでです。変えるには
`~/.mulmoterminal/config.json` に `maxIssueSessions`（1〜8）を書きます。

```json
{ "maxIssueSessions": 3 }
```

→ [同時に進める issue の数](config.html#max-issue-sessions)

## issue を一つ渡す {#one-issue}

ワークスペースのセルで、こう打ちます。

```
/mulmoterminal-issue-to-merge receptron/mulmoterminal#123
```

issue の URL でもよく、リポジトリがはっきりしていれば番号だけでも通ります。打ったセッションが
実装役になります。

1. issue、リポジトリ自身の決まり（`CLAUDE.md`、`AGENTS.md`、`CONTRIBUTING.md`。スキルの既定より
   こちらが優先します）、レビューの設定を読みます。
2. 要ることを「決まっている」「推測した」「決まっていない」に分け、**決まっていないことだけを
   聞きます**。推測したことも同じ問いに書くので、違っていれば直せます。決まっていないことが無ければ、
   何を推測したかを言って先に進みます。
3. 最新の既定のブランチから分け、実装し、リポジトリの検査を回して、PR を出します。
4. `requestReview` を呼びます。レビュー役のセルが現れ、働く様子を見られます。
5. 一往復が終わるたびに、`[requestReview]` で始まる行が実装役に打ち込まれます。判定、残りの往復の数、
   次にすることが書いてあります。修正を求められたら、本当の指摘をすべて一度の push で直し、次の往復を
   頼みます。
6. 行に **Merge condition met** とあれば、最新の push が動いていないことと CI が通っていることを確かめ、
   リポジトリの merge のしかたで merge します（決まりが無ければ merge commit）。レビュー役を閉じ、
   PR、かかった往復の数、レビュー役が見つけたものを報告します。

## issue をいくつも渡す {#several-issues}

ワークスペースのセルで、こう打ちます。

```
/mulmoterminal-dispatch-issues receptron/mulmoterminal#12 #15 #18
```

打ったセッションが **まとめ役** になります。

1. それぞれのリポジトリに `review` が書いてあるかを確かめます。無いものがあれば、進める前に聞きます。
2. **渡した順に**、上限まで実装役を起動します。それぞれに issue のワークツリー（ブランチは
   `issue/<番号>-<題名>`）と専用のセルが付き、上の「一つ渡す」流れをそのまま進めます。
3. どの issue がどのセルで動いているか、どれが待ちの列にあるかを伝えます。あわせて、**実装役の質問は
   それぞれのセルに出るので、そこで答えてほしい** と伝えます。
4. あとは待ちます。見に行くことはしません。何か起きるたびに MulmoTerminal が `[startIssueSession]` の
   行をまとめ役に打ち込み、まとめ役はそれに応じて動きます。

| 行の中身 | まとめ役がすること |
|---|---|
| PR が **merge された** | 待ちの列の次の issue を始めます。その実装役、レビュー役、ワークツリーは MulmoTerminal がもう閉じています。 |
| PR が merge されずに **閉じられた** | あなたに伝えます。残したもの（push していない作業のあるワークツリー）があればそれも。次を始めますが、同じ issue をやり直すのは頼まれたときだけです。 |
| **セッションが終わった** | あなたに伝え、`closeIssueSession` で閉じて、次を始めます。 |
| **あなたを待っている** | どの issue のどのセルかを伝えます。代わりに答えることはしません。 |

実装役のエージェントは、名指ししなければ `claude` です。同じメッセージで「実装役は codex で」と書けば
変わります。実装役になれるのは **claude、codex、copilot** で、レビュー役はそれとは別に、リポジトリが
決めたエージェントです。

待ちの列が空になり、すべての実装役が終わると、まとめ役は issue ごとに一行で報告します。PR と、
どう終わったかです。

## 画面での見え方 {#what-you-see}

**セル。** まとめ役のセル、動いている issue ごとに実装役のセル（見出しに issue のワークツリーが出ます）、
レビュー中の PR ごとにレビュー役のセルが並びます。どれもふつうのセルです。拡大して眺めることも、
打ち込んで答えることもできます。

**セッションに打ち込まれる行。** MulmoTerminal は、頼んだセッションに一行打ち込んで知らせます。PR が
merge されたときにまとめ役が受け取る行は、たとえばこうです。

```
[startIssueSession] receptron/mulmoterminal#3462 (session 3dac0f08-…): its PR #3463 was merged.
0 of 2 implementers are running; start the next issue if one is left. Closed implementer session
3dac0f08-…. Removed its worktree …/3462-readme-… and local branch issue/3462-readme-… (the remote
branch stays).
```

**GitHub ボード。** [GitHub ボード](github.html) では、PR のカードに書き込まれた判定の数が出ます
（**判定 2 回: LGTM**。最新の push がまだレビューされていなければ *前の push への判定*）。リポジトリが
求める数の LGTM が最新の push に付き、CI も通っていれば、**merge できます** の印が付きます。
`requestReview` と同じ決まりです。

**PR そのもの。** 往復ごとの判定は PR へのコメントになり、`REVIEW VERDICT: LGTM (head <sha>)` か
`REVIEW VERDICT: CHANGES REQUESTED (head <sha>)` で始まって、指摘が続きます。後から人が読む記録は PR です。

## 人が要るとき {#when-needed}

- **質問。** 実装役は自分のセルで聞きます。選択肢の画面が使えるエージェントなら、それで聞きます。
  まとめ役が起動した実装役なら、まとめ役にも伝わり、どのセルかをあなたに知らせます。
- **承認の確認。** claude と copilot の実装役は、自分で開いたセルと同じ確認で止まります。往復の途中で
  レビュー役が止まったときは、そのセルを添えて作者に一度だけ伝わり、あなたが答えれば往復はそのまま
  続きます。こうして起動した codex の実装役とレビュー役は、確認で止まりません（[下](#codex)）。
- **往復の上限。** `maxRounds` を超えると `requestReview` が断り、実装役は止まって聞きます。
- **同じ指摘が二度出たとき**、または issue が決めていない判断が要る指摘のときも、止まって聞きます。
- **フックや権限の決まりが merge を止めたとき。** そう報告して待ちます。回り道はしません。

自分の判断だけで merge するものはありません。merge するには、merge するその push で、リポジトリの
条件を満たしている必要があります。

## codex を実装役やレビュー役にする {#codex}

この流れのために MulmoTerminal が起動する codex（`startIssueSession` の実装役と、`requestReview` の
レビュー役）は、人が見ていなくても進みます。サンドボックスは有効のままで、仕事に要るところだけ
広げます。

- **ネットワーク。** `gh` で GitHub とやり取りするためです。
- **ワークツリーの git の管理情報。** 切り出し元のクローンにある、ワークツリー自身の git ディレクトリと、
  共通の objects・refs・logs です。実装役が commit と push をするためです。クローンの `config` と
  フックには書けません。`extensions.worktreeConfig` を有効にしたクローンでは、どこにも書けません。
- **承認の確認をしない。** サンドボックスが断った操作は失敗として codex に返り、codex はそのまま進みます。

codex が終わった後にセルを開き直して会話を再開しても、この許可は保たれます。自分で開いた codex の
セルや、ボードの **Start Work** から起動したものは、あなた自身のサンドボックスと承認の設定のままです。

## 片付け {#cleanup}

実装役の PR が **merge されるか閉じられる** と、MulmoTerminal は順に閉じます。レビュー役（セルと
レビュー用のワークツリー）、実装役のセル、手元のワークツリーとブランチです。**GitHub 上のブランチは
残す** ので、PR からたどれます。commit していない変更や、どこにも push していない commit がある
ワークツリーは **残し**、行にそう書きます。

**自分で終わった** 実装役は、起動したセッションに任せます。そのセッションが `closeIssueSession` で
閉じます。閉じられるのはそのセッションだけです。まだ作業中の実装役は、`force: true` が無ければ断ります。
まとめ役がそれを付けるのは、あなたが言ったときだけです。

まとめ役自身のセルは、終わっても開いたままです。ほかのセルと同じように閉じてください。

## うまくいかないとき {#troubleshooting}

| 見えること | わけと、すること |
|---|---|
| 「レビューの道具が無い」 | プロジェクトのセルで打っています。ワークスペースのセルから打ってください。 |
| レビューの段で、設定について聞いて止まる | リポジトリに正しい `review` のキーがありません。`"review": {}` を足すか、設定 → ディレクトリ設定で *ignored* を見てください。 |
| 上限で断られ、自分の実装役は一つも動いていない | このマシンのほかのセッションが枠を使っています。待つか、`maxIssueSessions` を上げるか、後でまとめ役にもう一度頼んでください。 |
| issue にもうセッションがあると断られる | その issue のワークツリーが使われています。そのセッションを終えるか閉じてからにしてください。 |
| レビュー役のセルが確認で止まっている | そこで答えてください。往復はそのまま続きます。 |
| 往復の数が数え直しになった | 往復はメモリの上で数えているので、サーバーを再起動すると数え直しになります。 |
| codex の実装役が GitHub に届かない、commit できない | 手で開いたセルか、13.8.0 より古いサーバーが起動したものです。今のサーバーで `startIssueSession` が起動した実装役には、[上](#codex) の許可が付きます。 |

## 道具の一覧（参考） {#tools}

スキルが使うもので、あなたが呼ぶことはありません。ワークスペースのセッションに渡されます。

| 道具 | すること |
|---|---|
| `reviewSettings { repo }` | リポジトリが決めたレビュー役、スキル、往復の上限、要る LGTM の数。 |
| `requestReview { repo, pr }` | レビューを一往復回します。決められたレビュー役を起動するか、前のを使います。すぐ返り、結果は後で打ち込まれます。 |
| `endReview { repo, pr }` | merge の後に、レビュー役を閉じてそのワークツリーを消します。 |
| `startIssueSession { repo, issue, agent }` | issue のワークツリーで実装役を起動します。`maxIssueSessions` まで。 |
| `closeIssueSession { session, force? }` | 自分が起動した実装役を閉じます。 |
| `sendToSession` / `waitForSessionReply` | 自分が起動したセッションに送り、その答えを読みます。 |

スキルは三つです。`mulmoterminal-issue-to-merge`（実装役）、`mulmoterminal-dispatch-issues`
（まとめ役）、`mulmoterminal-review`（レビュー役の既定）。同梱で、起動のときにスキルのフォルダへ
写されます。→ [機能リファレンス](features.html)
