# 社内向け — 必ず詰める点

- [ ] **ドメイン制限は二か所でかける**。ログイン時の関数（`beforeUserCreated` / `beforeUserSignedIn`）でドメイン外を拒否し、ルールでも `email_verified` とドメインを検査する。片方だけだと、関数の設定漏れかルールの書き漏れのどちらかで穴が開く
- [ ] **`email_verified` を必ず見る**。確認されていないメールアドレスは、誰でも名乗れる
- [ ] **役割はカスタムクレームに置く**。付与する関数は、呼んだ人が管理者であることを自分で確かめる
- [ ] **最初の管理者**は関数では作れない（付与できる人がまだいない）。一度だけ実行するスクリプトで付与し、その記録を残す
- [ ] **退職者**: Workspace でアカウントを止めても、発行済みのトークンはしばらく使える。`revokeRefreshTokens` を呼び、失効時刻を記録し、ルールで `auth_time` と比べて古いトークンを拒否する
- [ ] **監査ログ**は関数からだけ書く。クライアントからの書き込みはルールで拒否し、読めるのは管理者だけにする
- [ ] **機密情報を扱う**なら、保持期間と削除の手順を決めておく
