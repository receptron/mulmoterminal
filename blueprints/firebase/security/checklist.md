# Firebase — 必ず詰める点

- [ ] **ルールは既定で拒否**。`match /{document=**} { allow read, write: if false; }` を最後に置き、コレクションごとに開ける
- [ ] **ルールは試験で証明する**。エミュレータ上で「許されるべき操作が通る」と「拒まれるべき操作が拒まれる」の両方を書く。本番のプロジェクトに対して試さない
- [ ] **クライアントに管理者の鍵を置かない**。サービスアカウントの JSON をリポジトリにも画面にも入れない。Admin SDK は Cloud Functions の中だけで使う
- [ ] **利用者が書ける文書に権限を置かない**。役割はカスタムクレームで持ち、付与は関数だけが行う
- [ ] **App Check を有効にする**。Firestore と Functions の両方で強制する
- [ ] **開発と本番を分ける**。本番のデータを開発に持ち込まない
- [ ] **予算アラート**を本番に設定する。暴走した関数や読み取りの嵐は請求で初めて気づくことが多い
- [ ] **Firestore のリージョン**は作成時に決まり、後から移せない。データの置き場所の制約を確認してから作る
- [ ] `firebase.json` の Hosting に、`Content-Security-Policy` などのセキュリティヘッダーを付ける
