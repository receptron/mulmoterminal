# スキルごとの使われ方（#3437）

スキルを評価して直す仕組み（#3438）の入口。まず、どのスキルがどれだけ使われているかを見えるようにする。新しい測定や実行はしない。

## 使うデータ

- ライブラリの索引の `conversations.skills`。`conversation-fold.ts` が会話記録の `attributionSkill`（スキルが動いている間の応答に付く）から集めている
- 名前は claude が実行する名前のまま: プラグインのスキルは `plugin:slug`、ほかは slug。カタログの `CatalogSkill.id` と同じ形なので、そのまま突き合わせられる
- 数えるのは、ライブラリの一覧と同じ既定の絞り込み（`filterClause({})`）を通った会話だけ。`claude -p` / SDK、一時ディレクトリ、サイドチェーンは数えない。#3438 の評価は `claude -p` で走らせるので、評価の実行が使用回数に混ざらない

## 決めたこと

- 費用は出さない。会話の `cost_usd` は会話全体の費用で、スキルの分ではない。実データでは長い会話の中で一度呼んだだけのスキルに、会話全体の大きな費用が付いた。スキルの費用は #3438 の測定で、ありなしの差として出す
- 自分のスキルと、同じ名前のフォルダのスキルは、どちらも slug で記録されるので区別できない。両方に同じ件数を出す（`common/skillUsage.ts` に書いた）
- 索引が答えられないときは件数を何も出さない。「記録なし」と出すと、使われていないという主張になってしまう
- 部分インデックス `conversations_with_skills`（`skills != '[]'`）を足した。スキルを使った会話だけを読む。`create index if not exists` なので、スキーマの版は上げない。既存の索引にも、次に開いたときに付く

## 変更

- `common/skillUsage.ts`: 型、ガード、id から引く表
- `server/backends/library/index-queries.ts`: `skillUsage` / `skillUsageQuery`
- サービス、ワーカーの振り分け、`GET /api/library/skill-usage`（`{ skills }`。索引が開けないときは 503）
- `SkillsOverlay.vue`: 一覧の各スキルに件数か「記録なし」。右の欄に件数と最後に使われた日。カタログとは別に読むので、索引が遅くても一覧は待たない
- ガイド（en / ja）の Skills 画面の行

## 確かめたこと

- 実データの索引での集計（読み取り専用で開いた）: 一覧の既定の絞り込みを通すと、一時ディレクトリでのプラグインのスキルの大量の実行が外れた
- 使い捨ての HOME で起動したサーバーで、会話記録の例から件数と日付が出ること、使われていないスキルに「記録なし」が出ること
