# スキルの評価の課題を、実際にそのスキルが使われた会話から作る（#3470）

## 目的

課題は同梱スキル `mulmoterminal-skill-eval` が利用者と相談して作るが、作り物になりやすく、実際の使い方と合わないことがある。改善案を採用したあとに課題を足して測り直すときも、新しい課題を考える手間がかかる。

## 決めたこと

1. 会話は Library の索引から引く（`skillConversations`）。Library が一覧に出す会話だけを使うので、`claude -p` の実行は入らない。評価そのものの実行もこれで外れる。会話の記録を自分で探すと、評価の課題を「実際の依頼」として拾ってしまう
2. フォルダのスキルは、そのフォルダで開いた会話だけを使う。同じ名前のユーザーのスキルと、記録の上では区別できないため
3. 渡すのは新しい順に最大5件の記録の場所だけ。中身はサーバーで読まず、課題を作るセルの最初の指示に足す。Library が答えられないときは、何も足さない（今までどおりになる）
4. 同梱スキルには次を足す:
   - 会話は丸ごと読まず、スキル名で探す
   - 呼び出しの直前の利用者の依頼をもとに課題を作る
   - 名前・パス・秘密など個人的なことは取り除く
   - 会話のファイルは `files/` に写さない
   - どの課題が会話から来たかを利用者に伝える
5. 課題を「作る用」と「確かめ用」に分けることはしない。課題は最大20件で、判定に要る数より少ない。分けるとどちらも判定できなくなる。合わせ込みの確かめは、採用したあとに会話から新しい課題を足して測り直すほうが確か
