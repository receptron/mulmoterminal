# 振り返りの続き: 使った週に振り分け、モデル別とトークン数（#3395）

親: #3327。前段: #3335（PR #3390、`plans/feat-library-retrospective.md` の「後の PR に回す」二つ）。

## 実データで分かったこと

- `cost-state` は時刻を持たない累計。会話の途中にとびとびに書かれ、間が数日あくこともある。`modelUsage` にモデルごとの累計（`costUSD`、`inputTokens`、`outputTokens`、`cacheReadInputTokens`、`cacheCreationInputTokens`）があり、キーは `claude-opus-5[1m]` のように応答の `message.model` に添え字が付いた形。
- 応答は同じ `message.id` で何度も書かれ、同じ `usage` を繰り返す（大きい順 200 ファイルで約半分）。
- 累計が下がるのは、ほとんど `startTime` が変わった（数え直しになった）とき。いまの「最後の `cost-state`」は数え直す前の分を落とす。

## 決めたこと

- **振り分け**（`server/backends/library/spend-fold.ts` と `spend-split.ts`、どちらも純関数）: 取り込みでは二つを別々に持つ。応答ごとの重み（トークン数に料金の比率を掛けたもの。入力 1、キャッシュ書き込み 1.25、キャッシュ読み込み 0.1、出力 5。Claude のどのモデルでも同じ比率）を、書かれた 15 分の枠に、応答の id ごとに一行。会話のモデルごとの合計（金額とトークン数）。読み出すときに、モデルの合計をそのモデルの応答へ重みの比で分ける。同じモデルなら重みあたりの値段は一定なので、金額の記録の区間ごとに分けるのと同じだけ正しく、記録の間に持ち越す状態が要らない。そのモデルの応答がファイルに無ければ（サブエージェントのモデル、内訳の無い金額）全部の応答に重みで、応答が一つも無ければ会話の始まりに置く。最後の金額の記録より後の応答も、そのときまでに分かっている金額を分け合う。次の記録が来れば、読み出すたびに分け直すので正しくなる。
- **一つの応答は一度だけ数える**: 索引の `replies` は `(path, id)` を主キーにし、同じ応答のあとの記録は前の行を置き換える。記録がどれだけ離れていても一行（実データでは同じ id の記録は必ず隣り合っていたが、それに頼らない）。
- **数え直し**: 回（`startTime`）ごとに、各モデルの値の最高を覚える。前の回に戻ったら、その回の続きとして数える。会話の金額（一覧の `cost_usd`）は、回ごとの全体の最高の合計。全体の金額は一つの値として追う。モデル別の内訳がある記録ならモデルごとの最高の合計、内訳の無い記録なら `totalCostUSD` で、両方が混ざっても二重に数えない。内訳を超えた分は名前の無いモデルとして出す。
- **索引**: 新しい表 `replies (path, id, at, model, weight)` と、会話の行の `spend_models`（モデルごとの合計の JSON）。会話の状態に残るのは回ごとの合計だけで、応答は書き込みのたびに表へ渡して状態から外す。`LIBRARY_SCHEMA_VERSION` を 7 に上げ、作り直しは裏で一度。
- **振り返り**: 金額とトークン数は応答の時刻で週・プロジェクト・エージェント・モデルに分ける。会話の数と PR の数は、これまでどおり会話が始まった週に数える。モデル別の表を足し、合計の行にトークン数を出す。

## 受け入れ条件と試験

- 振り分けた金額の合計が、各回（`startTime`）の最高の `cost-state` を足したものと一致する（索引を通した試験）。
- 長い会話の金額が、使った時刻の週に入る。数え直しの前の分が落ちない。重複した応答を、記録がどれだけ離れていても二度数えない。

## やらないこと

- 足した行数（`lines_added`）の数え直しへの対応。金額と同じ問題があるが、振り返りは使っていない。
- Claude 以外のエージェント。索引は Claude の会話記録だけを読む。
