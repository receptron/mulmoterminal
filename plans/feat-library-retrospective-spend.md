# 振り返りの続き: 使った週に振り分け、モデル別とトークン数（#3395）

親: #3327。前段: #3335（PR #3390、`plans/feat-library-retrospective.md` の「後の PR に回す」二つ）。

## 実データで分かったこと

- `cost-state` は時刻を持たない累計。会話の途中にとびとびに書かれ、間が数日あくこともある。`modelUsage` にモデルごとの累計（`costUSD`、`inputTokens`、`outputTokens`、`cacheReadInputTokens`、`cacheCreationInputTokens`）があり、キーは `claude-opus-5[1m]` のように応答の `message.model` に添え字が付いた形。
- 応答は同じ `message.id` で何度も書かれ、同じ `usage` を繰り返す（大きい順 200 ファイルで約半分）。
- 累計が下がるのは、ほとんど `startTime` が変わった（数え直しになった）とき。いまの「最後の `cost-state`」は数え直す前の分を落とす。

## 決めたこと

- **振り分け**（`server/backends/library/spend-fold.ts`、純関数）: 二つの `cost-state` の差をモデルごとに取り、その間の応答に分ける。重みはトークン数に料金の比率（入力 1、キャッシュ書き込み 1.25、キャッシュ読み込み 0.1、出力 5。Claude のどのモデルでも同じ比率）を掛けたもの。応答の時刻で 15 分の枠に入れる。そのモデルの応答が間に無ければ全モデルの応答に、応答が一つも無ければ最後に時刻の分かった記録の枠に入れる。トークン数も同じ重みで分ける。分けた合計は差そのものなので、金額もトークンも足すと累計に戻る。
- **一つの応答は一度だけ数える**: 直近の `message.id` を覚え、同じ id の記録は重みを置き換える。
- **数え直し**: 回（`startTime`）ごとに、各モデルの値の最高を覚える。前の回に戻ったら、その回の続きとして数える。会話の金額（一覧の `cost_usd`）は、回ごとの全体の最高の合計。全体の金額は一つの値として追う。モデル別の内訳がある記録ならモデルごとの最高の合計、内訳の無い記録なら `totalCostUSD`（名前の無いモデルとして出す）で、両方が混ざっても二重に数えない。増えた分は、その記録で金額の増えたモデルに比例して配る。
- **時刻の無い金額**: 時刻の分かる記録がまだ一つも無いうちの金額は持っておき、最初に時刻が分かった枠に入れる。
- **重複**: 応答の id は金額の記録をまたいでも覚えておき、あとから来た同じ応答の記録は増えた分だけを数える。
- **索引**: 新しい表 `spend (path, at, model, cost_usd, input, output, cache_read, cache_write)`。会話の状態は毎回保存されるので伸ばさず、確定した分は書き込みのたびに表へ足して状態から外す。`LIBRARY_SCHEMA_VERSION` を 7 に上げ、作り直しは裏で一度。
- **振り返り**: 金額とトークン数は `spend` の時刻で週・プロジェクト・エージェント・モデルに分ける。会話の数と PR の数は、これまでどおり会話が始まった週に数える。モデル別の表を足し、合計の行にトークン数を出す。

## 受け入れ条件と試験

- 振り分けた金額の合計が、各回（`startTime`）の最高の `cost-state` を足したものと一致する（索引を通した試験）。
- 長い会話の金額が、使った時刻の週に入る。数え直しの前の分が落ちない。重複した応答を二度数えない。

## やらないこと

- 足した行数（`lines_added`）の数え直しへの対応。金額と同じ問題があるが、振り返りは使っていない。
- Claude 以外のエージェント。索引は Claude の会話記録だけを読む。
