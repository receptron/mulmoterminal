# スキルの評価の課題の同一性に、課題の始めのファイルも含める（#3491）

## 何が起きていたか

課題の組の同一性（`setHash`）は `cases.json` だけのハッシュだった。課題の始めのファイル `files/<課題>/` は、試行のたびにその時の中身が写されるのに、ハッシュには入っていない。始めのファイルだけを直すと、直す前の測定が今の課題の測定として扱われていた。影響したのは、改善の起点、一覧の印、次の一歩、採用前の確認、改善案の測定で写すスキルなしの結果。

## 決めたこと

1. ハッシュは `server/backends/skillEval/setHash.ts` の純粋な関数 `setHash` で出す。中身は `cases.json` と、`files/` の下の各項目（相対パス・種類・中身の要約）。並び順に左右されないよう、パスで並べてから足す
2. `files/` がない、または空の組は、ハッシュを `cases.json` だけのもの（今までと同じ値）にする。始めのファイルを持たない組の前の測定は、そのまま使い続けられる
3. 始めのファイルを持つ組は、一度だけ「まだ測っていない」になる。前の測定がどのファイルで測ったかは記録にないので、同じだと言える根拠がないため
4. ファイルは少しずつ読んで要約する（丸ごとは読まない）。リンクは辿らず、指す先の文字列で数える
5. 始めのファイルが読めない組は、読めなかった理由を添えて不正な組として扱う。どの組か見分けられないものを、今の組として出さない
6. 比べる側はすべて `readEvalSet` のハッシュを使っているので、変えるのはそこだけ
