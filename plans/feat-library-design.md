# ライブラリのデザインを決める（#3336、親 #3327）

実装の前に、ライブラリの見た目と動きを動く試作で決める。決まったことは `docs/library-design.md` に移し、以降のタスク（#3328〜#3335）はそこを参照する。

## 試作

`plans/feat-library-design/prototype.html`（ダミーデータ、英日、明暗、スマホ幅、キー操作）。上部の「試作」の帯は試作専用の切り替えで、アプリには入らない。

## 試作が提案している決定

### 骨格
- 既存の `FullScreenOverlay` の枠をそのまま使う。見出しは「ライブラリ」と、灰色で「会話・記憶・道具・容量」
- 枠の中は三段: 検索欄 → 分類の切り替えとプロジェクトの絞り込み → 一覧 | 読む画面
- 幅が狭いとき（760px 以下）は一覧だけを出し、選ぶと読む画面に切り替わる。戻るは「一覧」

### 検索
- 開くと検索欄にカーソルがある。`/` でいつでも戻れる
- 何か打つと **分類をまたいで** 結果を出し、分類ごとの見出しで区切る。切り替えの各分類には件数が出て、押すとその分類に絞る（もう一度押すと戻る）
- 一致した語は控えめな色で示す。会話は一致した発言の抜粋を 2 行まで出す
- 何も一致しないときは、何に一致しなかったかと、次に何をすればいいかを一文で

### 一覧の一行
- 1 行目がタイトル、2 行目が灰色の「プロジェクト · ブランチ · PR · いつ」。金額と増減行数は読む画面にだけ出す（一覧の情報量を増やさないため）
- 会話は「ピン留め / 今日 / 今週 / それより前」で区切る
- 行頭の小さな点が、直せる問題があることを示す唯一の印

### 読む画面
- タイトル、灰色のメタ情報の一行（プロジェクト、ブランチ、PR、金額、増減行数、いつ）、本文
- ユーザーの発言は左に細い線を引いた段落、返答は普通の段落（65 字幅まで）
- 道具の呼び出しは等幅の 1 行に畳み、押すと中身が開く。サブエージェントは点線の入れ子で、これも畳む
- 末尾に「変更したファイル」

### 操作
- 右下に、目立つボタンが一つ（会話は「再開」、記憶は「編集」、道具は「開く」、容量は「片付ける」）。`Enter` が常にこれを実行する
- それ以外は横の `more_horiz` の中。会話なら「ここから分岐 / ピン留め / 名前を変える / 昇格（記憶・規則・計画・issue）/ 書き出す」
- 消す操作はすべてごみ箱へ移すだけで、画面下に「取り消す」つきの短い知らせを出す
- 「片付ける」は、何を移すかを読む画面の中で確かめてから実行する（別窓のダイアログは使わない）

### 記憶
- プロジェクトごとに区切り、区切りの見出しに `MEMORY.md` の行数と上限の目盛り。上限の 9 割を超えると目盛りの色が変わる
- 問題があるときは、一覧の上に「n 件を整えられます」と一行だけ出し、「見る」で問題のあるものだけに絞る
- 読む画面では、問題を一文で（例: 挙げている関数が今のリポジトリに無い）、その下にファイル・種類・更新・出所（書いた会話へのリンク）
- 編集はその場で書き換える。`⌘ Enter` で保存、`Esc` でやめる

### 道具・容量
- 道具は、ディレクトリを一つ選び（右上の絞り込みがディレクトリ選択に変わる）、規則・権限・フック・スキルの四つを一覧に出す。各行の下に、それを決めているファイル
- 容量は「片付けられるもの」を先頭に、場所ごとの大きさを続ける。`cleanupPeriodDays` で消えるものと消えないものを一文で説明する

### 振り返り
ライブラリには入れない。#3335 は既存の `/usage` の中に置く（原則 6: 一覧を集計表にしない）。

### 見た目
- 色はアプリのテーマの値だけを使う（試作は Midnight と Daylight）。新しい色は足さない。問題の点は `--warn`
- 書体は `system-ui` と、アプリの等幅書体。大文字化はしない（プロジェクト名や設定名は識別子なので形を変えない）
- アイコンは Material Symbols（outlined）だけ。絵文字なし

## 確かめたこと
- 試作を 1280px と 390px、明暗、英日で撮り、横あふれとコンソールのエラーが無いことを確かめた
- 既存の全画面ビューと同じ枠・色・書体であることは、`FullScreenOverlay.vue` と `src/style.css` の値から作っている。実際のアプリと並べた比較はまだ
