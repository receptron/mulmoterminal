## 一つ目の PR（閲覧）

- 場所は Claude Code の `<projects>/<slug>/memory/`。slug は Claude Code 自身の規則（`[A-Za-z0-9_-]` 以外を `-` に）で、`projectSlug` として同じ規則を持つ。索引が知っている会話のディレクトリを slug に直して、フォルダにディレクトリ名を付ける。知らないものは slug のまま
- `MEMORY.md` の読み込み上限は Claude Code 2.1.292 の本体に書かれた値（200 行・25,000 バイト）。どちらかの 9 割を超えたら目盛りを警告の色にする
- 実データでは project フォルダが 1 万を超え、記憶があるのは 51 個（608 ファイル）。一覧は 64 個ずつ読み、空のフォルダは出さない。暖まった状態で約 0.4 秒
- 本文は wiki と同じ描画（`renderWikiHtml`: frontmatter を落とし、`[[name]]` をリンクの span に、marked のあと DOMPurify）。同じプロジェクトに無い名前のリンクは押せない形にする
- frontmatter の読み取り（`parseMemoryFrontmatter`）は平らなキーと `metadata:` の一段だけ。知らないキーも残す（三つ目の PR で書き戻すときに消さないため）
- 要求はパスを持たない。フォルダは slug、ファイルは名前で、どちらも Claude Code が付ける形を確かめてから projects の下に組み立てる。リンクのファイルは読まない
- 分類のつまみは「会話 / 記憶」の二つ。上下キーは記憶の一覧も動く。`Enter` は三つ目の PR（編集）で使う
- 検索欄は分類をまたいで効く: 会話は今までどおりサーバーで、記憶は名前・説明・ファイル名で手元で絞る。結果を分類ごとの見出しでまとめる表示（設計の「Search」）は、記憶が増えてから
