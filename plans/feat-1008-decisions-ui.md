# 判断ログを見る画面

Issue: #1008（#997 の続き、#991 段階 1）

## この画面が答える問い

「これまで何を聞かれ、何を選んだか」。#997 で API は入ったが、**誰も呼んでいなかった**。

## 1 行 = 1 問い（1 判断ではなく）

`AskUserQuestion` は 1 回で複数のことを聞ける。そして**この画面で一番効く操作は「選択肢が
外れていたものだけ見る」**で、それは問い単位の性質なので、行も問い単位にした。

## `answerKind` の 3 値を分けて出すのが目的

| | 何を意味するか | 出し方 |
|---|---|---|
| `option` | 提示した選択肢から選ばれた | 選ばれた選択肢を強調 |
| `free-text` | **選ばずに自分で書いた** | 左に色帯 + 答えを強調 |
| `unanswered` | 聞いたが答えが返らなかった | フィルタで分離 |

後ろの 2 つは**答えの情報ではなく問いの情報**で、平坦なリストでは消える。だからフィルタは
この 3 値そのものにした。件数を各フィルタに出すので、「今日 13% が自由記述だった」が数えなくても
見える。

`options[]` の description をそのまま出すのも意図的で、**選ばなかった方の帰結**がそこに書いてある。
#991 が「判断に必要な情報」として挙げたもののうち、すでに書かれている唯一のもの。

## 空の状態を 3 つに割る

`{ decisions: [], scanned, unreadable }` は 3 つの異なる事実になる。

- `scanned 0` → セッションが無い
- `scanned > 0, decisions 0` → 何も聞かれていない
- `unreadable > 0` → **読めなかった transcript がある**（#998 の 585MB 問題がここに出る）

3 番目を黙って「判断なし」にすると、**部分的な答えが全体の答えに見える**。結果が出ているときも
上部に注意書きを出す。

## どこから開くか

- **ツールバー**（グリッド時）: サーバのワークスペースを対象にする。ツールバーは特定の
  ディレクトリを代表しないため
- **ターミナルヘッダー**: `open: { view: "decisions" }` でそのセルのディレクトリを対象にできる
  （`?cwd=`）。既定のヘッダーボタンには**追加しない** —— 既定の並びを全員分変えることになるため

API が cwd をフォールバックしない（#999 の Codex レビュー）ので、画面側が対象ディレクトリを
決める必要がある。上の 2 経路はその答え。

## 境界

読むだけ。編集も自動化も提案もしない（#991 段階 3 以降）。原本は Claude Code の transcript。
