# 振り返り（#3335）

親: #3327。デザイン（`docs/library-design.md` 原則 6）どおり、ライブラリの一覧ではなく `/usage` に置く。

## 一つ目の PR

- ライブラリの索引から、直近 12 週の金額・会話数・つながった PR の数を、週ごと・プロジェクトごと・エージェントごとに出す。公式の `stats-cache.json` には頼らない
- 数えるのはライブラリが一覧に出す会話（`claude -p` や一時ディレクトリや分岐は除く）。会話の金額は、会話記録の `cost-state` の最後の値（索引の `cost_usd`）。会話は始まった週に数える
- 計算は純関数（`server/backends/library/retrospective.ts`）。週は月曜のローカルの 0 時から。索引からは会話ごとの行だけを取る（`retrospectiveRows`）
- 受け入れ条件「金額の合計が `cost-state` を素直に足したものと一致する」は、索引を通した試験と、実際の索引での SQL の直接の合計との一致で確かめた
- `/usage` はローテーションが無くても開けるようにした（メニューの出し分けから外した）。トークンの枠は、トークンがあるときだけ上に出す。画面とメニューの名前は「使用量」
- 後の PR に回す: モデル別とトークン数（索引に列を足し、作り直しが要る）、長い会話の金額を使った週に振り分けること（いまは始まった週にまとめて入る。実際の索引で、9 月末から 11 月まで続いた一つの会話が一週に大きく出た）
