## 一つ目の PR（指示ファイル）

- 読む順と場所は Claude Code の説明（code.claude.com/docs/en/memory）に合わせる。純関数 `instruction-files.ts`:
  - 組織の `CLAUDE.md`（macOS / Linux / Windows でそれぞれの場所）、自分の `CLAUDE.md`（設定フォルダ。`CLAUDE_CONFIG_DIR` に従う）、自分の `rules/`
  - ファイルシステムのルートから作業ディレクトリまで、各ディレクトリの `CLAUDE.md` と `CLAUDE.local.md`（同じディレクトリでは `CLAUDE.local.md` が後）。作業ディレクトリでは `.claude/CLAUDE.md` も
  - プロジェクトの `.claude/rules/` の `.md`（下のフォルダも）。frontmatter に `paths` があるものは「当てはまるファイルを扱うときだけ」
  - `@path` の取り込み: そのファイルのフォルダから解く、`~/` はホーム、`\ ` で空白、引用符で囲んだものとコードの中は取り込まない、四段まで、同じファイルは一度
  - `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md` が作業ディレクトリにも上にも無いときは、代わりに各ディレクトリの `AGENTS.md` と `.claude/AGENTS.md`（既定の設定のとき。自分の `CLAUDE.md` と組織のものは数えない）
  - 4 MiB を超えるファイルは Claude Code が読まないので「読まれない」と出す
- 下のディレクトリの `CLAUDE.md` は、そこを触ったときに読まれるもので起動時ではないので、出さない。`claudeMdExcludes` と「どの指示ファイルを読むか」の設定は、この PR では見ない
- 経路はパスを受け取らない側に寄せる: ディレクトリは会話が動いたことのあるものだけ（`directories`）、ファイルはそのディレクトリの一覧に出たものだけ。中身はリンクの先も読む（Claude Code がたどるので）
- 実機の確かめ: このリポジトリで一覧を出し、このセッションの起動時に Claude Code が読み込んだファイル（`~/.claude/CLAUDE.md`、`~/ss/llm/CLAUDE.md`、このリポジトリの `CLAUDE.md`）と同じ三つが同じ順に出ることを見た

## 二つ目の PR（設定の重なり）

- 読むのは自分（設定フォルダの `settings.json`）、プロジェクト（`.claude/settings.json`）、ローカル（`.claude/settings.local.json`）、組織（OS ごとの `managed-settings.json`）。重ね方は Claude Code の説明（code.claude.com/docs/en/settings の Settings precedence）どおり、組織 > ローカル > プロジェクト > 自分
- 権限（`allow` / `ask` / `deny`）はリストなので全部のファイルのものを足す。環境変数は変数ごとに、ほかの最上位のキーはキーごとに、いちばん強いファイルの値。フックはイベントごとに全部のファイルのものを並べる。どれにも、決めたファイルを添える
- JSON のオブジェクトでないファイルは「JSON ではないので読まれない」と出し、重ねない。読み方は指示ファイルと同じ（リンクはたどるが、ネットワーク上のパスはたどらない）
- 範囲の外: `--settings` と環境変数（その場の起動だけのもの）、プラグインが足すフック、MCP（別のファイルなので次の PR）、ローカル設定をリポジトリの根に置く場合（いまは作業ディレクトリの `.claude` だけを見る）
- 画面: 道具の一覧のいちばん上に「設定（重ねた結果）」の行。選ぶと読む画面に重ねた結果を出す
- 実機の確かめ（読むだけ）: このリポジトリでは自分の `settings.json` だけがあり、許可のルール・環境変数・そのほかのキーがすべて「自分」と出た

## 三つ目の PR（参照の検査）

- 指示ファイルを読む画面に、そのファイルが挙げているのに見つからないパスを一行で出す（追加の要望「CLAUDE.md などでファイルを参照しているときに、それが正しいか」）
- 挙げているパスは、Markdown のリンク先（marked の字句解析で、コードの中は除く。ウェブのアドレス・メール・同じページの見出しは除く）と、コード表記のパス（記憶の健康診断と同じ `pathReferences`）
- 相対パスは、そのファイルのフォルダと作業ディレクトリの両方で探し、どちらかにあれば見つかったとする。ネットワーク上のパスは問い合わせず、見つからないとも言わない。一つのファイルで調べるのは 200 件まで
- 例として書かれたパスは除く: 置き換え用の名前（`xxx`、`foo` など）と、ドットで始まるフォルダ（`.cursor/…` のような道具の設定。そのプロジェクトのファイルではないことが多い）。実際の CLAUDE.md で試し、出た誤りはこの二種類だけだった
- 実機（読むだけ）: このリポジトリの CLAUDE.md で、`backends/files/fileOps.ts`（実際は `server/` の下）と `src/config/apiRoutes.ts`（MulmoClaude 側のファイル）の二つが出た


## 四つ目の PR（スキルの編集）

- 追加の要望「skill 編集はしたいよね」。Skills 画面で、読んでいるスキルの `SKILL.md` を **編集** でその場で直せる（`⌘Enter` で保存、`Esc` でやめる。`Esc` は画面を閉じない）
- 編集できるのは自分のスキル（`~/.claude/skills`）とフォルダのスキル（`.claude/skills`）だけ。プラグインのスキル（プラグインの更新で書き戻される）と、自分のフォルダにある MulmoTerminal 同梱のスキル（起動のたびに書き戻される）は読むだけ
- 保存は記憶の編集と同じ書き方（`writeMemory`）: 開いたときの本文（SHA-256）のままのときだけ書き、変わっていたら 409 で「読み直す」を出す。リンクは書かない。書く先は既存の `allowedRoot`（有効なプラグイン、ターミナルが動いたフォルダ）で決まる
- `GET /api/skills/doc` は編集できるときに `editable` と `version` も返し、`PUT /api/skills/doc` で保存する
- 確かめ: 作業用の HOME でサーバーを動かし、読み出し・保存・古い版での保存（409）・同梱スキル（400）を HTTP で確かめた
- スキルを改善するスキルをどう持つかは別に決める（この PR の範囲の外）
