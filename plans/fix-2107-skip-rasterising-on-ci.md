# fix-2107: あのランナーは、どの予算でも当てにならない

## 経緯（予算を3回変えて、3回とも赤）

| 予算 | 結果 |
|---|---|
| puppeteer 既定の 30 秒 | flake。daily 12 run 中 5 回失敗（#2095） |
| 30 秒 × 3 試行（#2096 の retry） | 半減したが、その PR 自身の run で赤。1件は 33.7 秒で復帰、1件は 93.7 秒で失敗 |
| **60 秒**（上流修正 `@mulmoclaude/shapescript-plugin@6.2.0`） | **また赤**。run 35193394490、`main` の `d7d07561` で **3件中2件**が `Navigation timeout of 60000 ms exceeded`、ファイル全体で 125 秒 |

最後の行が決定的。**修正が入った状態で、ページ読み込みが1分を超える**。ページが必要とするものは
全てディスクから供給されているので、遅いのは Chromium が GPU の無い共有ランナーでソフトウェア GL の
three.js を評価する時間。次の数字を選んでも同じことになる。

## なぜ Windows CI だけで走っているのか

ピクセル系は `it.runIf(canRender)` で守られていて、`~/.cache/puppeteer` をキャッシュしているのは
`windows-pr.yaml` と `windows-daily.yaml` だけ。`ci.yml`（ubuntu / macOS）はしないので、そちらは
最初からスキップしている。**CI で走るのは Windows だけ**で、しかも設計意図ではなくキャッシュの
副作用。spec 自身のコメントは「開発機で走る。レンダリングの退行はそこで捕まる」と書いている。

## 直し方

`CI` が立っていたら**走らせない。probe もしない**。probe 自体がレンダなので、ブラウザのある唯一の
CI ではスキップを決めるためだけに1分使っていた。

これで全 CI の挙動が揃う（ubuntu / macOS は元からスキップ）。

## 失うもの（隠さず書く）

ピクセル系が持っていたホスト側の主張 —— 保存先が**絶対パス**で、ワークスペースの `artifacts/renders`
の下にあること —— が CI で検証されなくなる。引数契約と拒否系は全環境で走り続ける。ブラウザ無しで
保存パスを検証する follow-up は別途。

## やらないこと

- **予算をまた上げる**。30 → 60 と上げて、どちらも赤。次は 120 秒？ 追いかけているだけ。
- **retry を戻す**。#2096 で試して半減しただけだった（しかも隠す方向のリスクを抱える）。
- **puppeteer キャッシュを CI から外す**。ブラウザが消えると `headlessPreview.spec.ts` も
  スキップになり、こちらの意図とは別のものまで落ちる。

## 検証

- `CI=1` で3件がスキップされ、残り4件が通ること（しかも一瞬 —— 以前は probe だけで1分かかっていた）。
- `CI` を外すと**実際に走る**こと。黙ってどこでもスキップが一番危ない失敗なので、そこを確認する。
