# fix #2003 — セルの forum メニューが画面外へ出てスクロールできない

## 問題

`TerminalCell.vue` の forum（ask）メニューのコンテナに **`max-height` も `overflow` も無い**:

```
absolute right-0 top-full z-20 mt-1 flex min-w-[180px] flex-col rounded-md border ...
```

中身の `askTargets` は `pickHandoffTargets`（`src/composables/useHandoff.ts:38`）が
**自分以外の全スロットを無制限に**返す。20 セルなら 19 行が並び、その下に積まれた
`RoundTableMenu` の設定と Start が画面外へ落ちる。`absolute` なので親のスクロールにも乗らず、
ホイールも効かない。報告者はブラウザのズームを 50% にして回避していた。

## これは設計判断ではなく取りこぼし

同リポジトリの他のドロップダウンは 3 つとも既に同じ対策をしている:

```
src/components/MulmoMenu.vue:103   … min-w-[180px] max-h-80 overflow-y-auto flex flex-col …
src/components/RunMenu.vue:56      … min-w-[180px] max-h-80 overflow-y-auto flex flex-col …
src/components/SkillMenu.vue:76    … min-w-[180px] max-h-80 overflow-y-auto flex flex-col …
```

forum メニューだけが漏れている。

## 計画の前提が 1 つ間違っていた（実測で判明）

当初は「可変長なのは ask リストだけで、`RoundTableMenu` は固定高のフッタ」と考えていたが、
実ブラウザで測ると **`RoundTableMenu` の席チェックボックスもターゲット数ぶん並ぶ**。
19 ターゲットでの内訳:

| 部分 | 高さ | 可変か |
| --- | --- | --- |
| ask リスト | 798px（19 行 × 42px） | 可変 |
| 席リスト | 722px（19 行 × 38px） | **可変** |
| 操作部（turns / room / Start / watch） | 216px | 固定 |
| メニュー合計 | **1750px**（ビューポート 800px） | — |

つまり可変長のリストが 2 つある。フッタを丸ごと固定にする案は成立しない。

## さらに: CSS だけでは解決しない

上限を `max-h-[calc(100vh-5rem)]` で付けたところ、メニュー高さは 720px に収まり
リストもスクロールするようになったが、**Start はまだ画面外**だった（menuBottom 864 > 800）。
メニューはボタンにぶら下がって開くので、「許される高さ」と「下に収まる高さ」は別の数字で、
ビューポート単位は後者を知らない。最下段のセルでは後者がほぼゼロになる。

→ 開いた瞬間に計測して、**入る側に開き、その側の残りを上限にする**。
規則は `src/composables/menuPlacement.ts` に純粋関数として切り出す（ブラウザ無しで試験できる）。

## 直し方

兄弟をそのまま真似ると**メニュー全体**がスクロールする。それでも報告者の要求は満たすが、
このメニューだけは**可変長のリストと Start ボタンが同居**しているので、Start に触るたびに
19 行スクロールすることになる。一段良くする:

- メニュー: `flex flex-col overflow-y-auto` + **開いた瞬間に計測した** `max-height`、
  余白が下に足りなければ `bottom-full`（上向き）に開く
- **2 つのリストをそれぞれ** `min-h-[2.5rem] … overflow-y-auto` で包む
  （`cell-ask-list` と `round-table-seats`）。空のときは描画しない
- 操作部は `flex-none` → 縮まない。規則は「この列の直接の子は、**席リストか `flex-none` のどちらか**」
  という形で spec に固定した（コントロールを 1 つずつ数え上げると、数え上げた表から漏れる）

縮むのはリストだけ、操作部は縮まない、という形。ただし**操作部が「常に見える」とは書けない**
（下記 round 2 の訂正）。メニューが極端に短いときは外側がスクロールし、操作部はスクロールで
到達できる、が正確な言い方。

報告者の「せめて round table に手が届くこと」と「スクロールして読めること」を両方満たす。

## やらないこと

- **「席は最大 5 なのにメニューは全ターミナルを並べている」**（報告者も「別の話」と明記）。
  スクロールが付けば実害が消えるので、別イシュー。数を絞ると「どのセルと話すか」の
  選択肢を勝手に狭めることになり、それ自体が判断を要する。
- **兄弟メニュー（`MulmoMenu` / `RunMenu` / `SkillMenu`）**。`max-h-80` の固定上限を持つが、
  同じ理由で最下段では収まらない（潜在的に同じ不具合）。この PR の範囲外。
- **「席は最大 5 なのにメニューは全ターミナルを並べている」**（報告者も「別の話」と明記）。

> **訂正（当初はここに「上向きに開くのは範囲外」と書いていた）**: 上限を付けただけでは
> 最下段のセルで Start が画面外に残ることが実測で分かったため、**反転は実装した**。
> `menuPlacement()` がその判断を持つ。

## 検証

- **実ブラウザで見る。** jsdom はレイアウトを持たない（高さが常に 0）ので、
  overflow のバグは jsdom のユニットテストでは原理的に捕まえられない。
  アプリの**実際のビルド済み CSS** を読み込んだページに、同じクラスの markup を
  19 行ぶん描画して、①フッタ（Start）が可視 ②リストがスクロールする ③メニュー全体が
  ビューポートに収まる、を実測する。修正前後の両方で測って差を出す。
- コンポーネント spec で、スクロール領域が**リスト側**にあり `RoundTableMenu` が
  その外にあることを固定する（クラスの有無ではなく DOM の入れ子関係を見る）。
- `yarn format` → `lint` → `build` → `typecheck` → `test`。

## round 2 の訂正（Codex レビューで判明）

実装は 2 度直っている。plan の上の記述は**現在の実装に合わせて更新済み**だが、何が変わったかを残す:

1. **`overflow-hidden` → `overflow-y-auto`（外側）。** `MIN_MENU_HEIGHT_PX` を 220 にしていたが、
   これは縮まない chrome（216px）より低い。下に 220-260px しかない位置では下向きのまま
   `overflow-hidden` に切られ、**報告されたバグが閾値の守るはずの位置で再発**していた
   （実測: max-height 180/220px で `startBottom > menuBottom`）。
   閾値を上げるだけだと正しさが「DOM と同期し続ける数字」に依存するため、外側をスクロール
   させて**切れる状態自体を除去**した。MIN は 220 → 320 に上げたが、役割は「窮屈か」だけに降格。
2. **リストの `min-h-0` → `min-h-[2.5rem]`。** Codex の caveat（「Start は席を選ぶまで disabled
   なので席が選べるかも測れ」）が実際の穴だった。320px 未満で席リストが高さ 0 に潰れ、
   クリック不可（`seatIsHitTarget: false`）。Start に届いても round table は始められない。
3. **空リストは描画しない。** 2 の下限は、ターゲットが 0 件のとき
   「No other terminal to read」の上に 40px の死んだ余白を作っていた（実測）。
   グリッドにセルが 1 つだけ、という一番ありふれた場合に出る。

## 実測（実ブラウザ・実ビルド CSS）

| | 修正前 | 修正後 |
| --- | --- | --- |
| メニュー高さ / Start | 1750px, bottom 1894, 不可視, スクロール要素なし | 上段 624 / 中段 364 / 下段は反転 688、いずれも Start 可視 |
| max-height 120-420px の Start | — | 全域で到達可能（320px 未満はスクロールで） |
| 席のクリック可否 | 120-260px で `seatBoxH` 0-9px, `hit:false` | 全域で 40px+, `hit:true` |
| 空リスト時 | リスト 40px + メッセージ top 45 | メニュー 37px, メッセージ top 5 |

### round 3 の訂正

`flex-none` を「操作部に付けた」と書いていたが、**Start と room のエラー行に付いていなかった**
（Codex round 3, P3）。`stop` は `mx-1 cursor-pointer`、`watch` は `mx-1 mb-1 … truncate`、
`start` は `mx-1 mb-1 cursor-pointer` — 置換パターンが Start だけ素通りしていた。
1 箇所直して兄弟を落とす典型。

直したうえで、spec を**許されるものの列挙**に書き換えた: 席リスト以外の直接の子はすべて
`flex-none`。既知の取りこぼしも、将来足される未知の子も赤になることを確認済み。
