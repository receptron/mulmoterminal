# 会話と成果物の紐付け（#3330）

親: #3327。設計は `docs/library-design.md`。

## 一つ目の PR（PR と会話の行き来）

- 索引は新しい表を作らない。会話の行に `prs`（会話記録の `pr-link` を集めた JSON）が既にあるので、`json_each` で引く（`prCreators`）
- 問い合わせは「このリポジトリの、この PR 番号たち」を一度（`GET /api/library/pr-creators?repo=owner/repo&numbers=…`）。答えは PR ごとに作った会話を一つずつで、一覧に出ている PR の数を超えない。リポジトリ単位で会話を全部返す形にすると、上限で一覧の PR が切れることがあった
- PR を記録した会話は全体のごく一部（実データで約 10 万件中 400 件ほど）なので、`prs != '[]'` の部分索引を張る。スキーマは開くたびに流しているので、既存の索引も作り直さずに索引だけ足される
- 「この PR を作った会話」は、その PR を記録した会話のうち **始まりがいちばん早いもの**。後からレビューや修正で戻ってきた会話より、開いた会話を選ぶ
- 選ぶ対象はライブラリの一覧に出る会話だけ（`claude -p` / SDK の実行、一時ディレクトリ、サイドチェーンは除く）。ボタンで開く会話が、ライブラリに無いものにならないように
- リポジトリ名は大文字小文字を区別しない（GitHub と同じ）。`owner/repo` 以外の形と、`.` だけの名前は 400。ホスト付きの名前（`gitlab.com/group/project`）は画面側で問い合わせない（`pr-link` は GitHub のもの）
- ボタンの読み上げ名には PR 番号を入れる（同じ名前のボタンが並ぶと区別できない）
- ボタンは PR の行の横に置く。行そのものが GitHub へのリンクで、リンクの中にボタンは置けない
- 引けなかったときはボタンを出さないだけ。GitHub ビューの本分は PR の一覧
- 読む画面の灰色の一行の PR 番号はリンクにする。会話記録に書かれた URL なので、`https://github.com/` で始まるものだけ開く

## 二つ目の PR（変更したファイル）

閲覧だけ。ファイルを戻す操作は入れない（issue の推奨どおり、使われ方を見てから）。

- 記録は二種類ある。ユーザーの発言ごとの `file-history-snapshot`（その時点で追っている全ファイルと、そのターンで編集する前の写し）と、ターンの途中で一つ足す `file-history-delta`（v1 = 会話が初めて触る前の状態。無かったファイルは写しの名前が null）。両方をファイルと版で束ねる（`foldFileHistory`、純関数）
- 写しは `~/.claude/file-history/<セッション>/<16桁の16進>@v<n>`。版をつなぐと v1 → v2 → … → 今 になり、一つずつがそのターンの変更。既定は「会話全体」（最初の版 → 今）
- 索引には入れない。読むときに会話記録を一行ずつ流して `"file-history-` を含む行だけを読む。同じ会話記録は大きさと更新時刻が変わるまで覚えておく（一覧のあとに中身の問い合わせが続くため）
- 要求が名指しするパスは読まない。ファイルは会話記録が追っていたものをその追跡パスで選び、写しはそのセッションのディレクトリから記録どおりの名前で読む。名前の形も確かめる
- 1 MB を超えるもの、NUL を含むもの（テキストでないもの）は読まずに理由を返す
- 名前のある写しが消えていたら「読めない」。「無かった」として返すと、そのターンでファイル全体を作ったように描いてしまう
- 一覧に出るのは Claude Code の編集ツールで変えたファイルだけ。スクリプトやシェルでの変更は出ないので、画面にそう書く

### 確かめたこと（git との照合）

ownplate の実際の会話（`00137b9d…`）で、一覧の 5 ファイルが会話中の Edit / Write の対象と一致した。リポジトリ内の 3 ファイルは、全部の版（v1・v2・v3・今）が git に記録された中身とハッシュで一致し、版の切れ目がコミットに対応した（v1 は会話前、v2 と v3 はその会話のコミット）。git には一覧に無い変更もあるが、それはシェルで変えたもの。
