# ライブラリ 6: 容量と片付け（#3333）

親: #3327。`~/.claude` に溜まり続けるものを、安全に、分かる形で片付けられるようにする。

## 決めたこと（2026-11-21）

- 二つの PR に分ける。どれも単独で戻せる
  1. **見る**（この PR）: 分類「容量」。`~/.claude` の場所ごと・プロジェクトごとの大きさと、`cleanupPeriodDays` の値。読むだけ
  2. **片付ける**: 片付けの候補と、ごみ箱へ移す操作（取り消しつき）
- ごみ箱はシステムのごみ箱（記憶の削除と同じ）。空にするのは OS に任せる。Windows では片付けを出さない
- `cleanupPeriodDays` は文書にあることだけ言う: 値（既定 30 日）と、Claude Code が起動時にそれより古い会話の記録を消すこと。ほかのフォルダの掃除は版ごとに変わり、公開された説明がないので、フォルダごとには書かない
- 動いているセッションの保護（二つ目の PR）: MulmoTerminal が動かしているセッションに加えて、24 時間以内に変わったものは候補にしない

## 一つ目の PR（見る）

- 大きさは専用のワーカースレッドで測る。索引のワーカーは一回の呼び出しが長いと打ち切るので使わない。サーバーの主スレッドも止めない
  - 測るのは `~/.claude`（`CLAUDE_CONFIG_DIR` があればそこ）の直下の項目ごとと、`projects/` の下のプロジェクトごと
  - ディスク上の占有量（`du` と同じ。`blocks` が無い環境はファイルの大きさ）。シンボリックリンクはたどらない。読めないものは数えて先へ進む
  - 測った結果はサーバーが覚えておく。画面は測り直しを `POST` で頼み、途中は進み具合を出す。`GET` は読むだけ
- プロジェクトのディレクトリは、ライブラリの索引にある会話の `cwd` から、Claude Code と同じ規則で名前を作って突き合わせる。一時パス由来かどうかは索引と同じ判定
- `cleanupPeriodDays` は `~/.claude/settings.json` から読む。無ければ既定の 30 日、読めなければそう言う（純関数）
- 画面: 種類の切り替えに「容量」。左に場所の一覧（大きい順、上に合計）、右に選んだ場所の大きさ・ファイル数、`projects/` ならプロジェクトの一覧（大きい順、一時パス由来の印）、下に `cleanupPeriodDays` の一文。検索欄はプロジェクトを絞る
