# ライブラリ 7-2: 繰り返し指示の検出（#3334 の二つ目）

親: #3327。#3334 の一つ目（昇格、#3366）の続き。何度も打っている指示を見つけて、規則かスキルにできるようにする。

## 決めたこと（2026-11-21）

- 出す場所: ライブラリに種類「繰り返し」（会話・記憶の次）。開かなければ何も出ない
- 候補からできること: 規則にする / スキルにする。昇格と同じく、プランモードのセルで同梱スキル `mulmoterminal-library` が案を作る（`repeat <rule|skill> <id>`）。サーバーからスキルへ渡すのは候補の id だけで、文はスキルが `GET /api/library/repeats/:id` から読む
- 判定: 直近 90 日に、2 セッション以上で 3 回以上。完全に同じもの（幅・大文字小文字・空白・句読点・リンクを無視）はプロジェクトをまたいでも数える。80 文字以下の指示は、同じプロジェクトの中で文字の 2 字組の 7 割が重なれば一つにする
- 除くもの: スラッシュコマンド、`!` の行、`[Pasted text #…]`、一時ディレクトリのプロジェクト、索引が自動・一時・サブエージェントとする会話、ごく短い返事（整えて 6 文字未満）

## 実データで分かったこと（読むだけで測った）

- 索引の会話と結びつくプロンプトは一部だけだった（記録の無い実行や、古くて記録が消えた会話が多い）。結びつきを条件にすると、拾いたい繰り返しの大半を落とす
- そのため履歴（`history.jsonl`）を直接読む。索引は、プロンプトを打ったディレクトリを持っていないので
- 「自動の実行」は、会話の印だけでは見分けられなかった。最大の雑音は、このリポジトリの使用量の試し測りが打つ 1 文（各セッションに 1 文とスラッシュコマンドだけ）と、予定した作業の文（各セッションに 1 文だけ）。そこで「打った文（コマンド以外）が 1 つしかないセッション」も数えない
- URL どうしは文字の組が多く重なり、別の issue の URL が一つにまとまってしまう。比べる前に URL を一つの印にする（URL だけの文は短すぎて落ち、「調査して <URL>」は一つの型として残る）
- 似ている度合いのしきい値 0.7: 0.6 では「マージしてタグ打って」が「CI通ったらマージして」に混ざった
