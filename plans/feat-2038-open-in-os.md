# #2038（後半）— OS の既定アプリで開く / クリックの行き先

前半（[#2045](https://github.com/receptron/mulmoterminal/pull/2045)）でバイナリを
エディタに流し込むのを止め、「プレビューできない」面を出した。残りの 2 部品を入れる。

## 1. `POST /api/files/open`

`reveal.ts`（#2039）と対になる。動詞が違う — こちらは**ファイルを開く**（xlsx なら Excel）、
あちらは**場所を見せる**。ルート名と `{ok:true}` の契約は MulmoClaude の `/api/files/open` に
合わせ、WSL を見る点だけ意図的に違える（`openDirCommands()` を再利用、#1447）。

正規化は **stat の前**。#2039 で払った P2（`path.resolve` は `..` を字句的に、カーネルは
symlink を辿って畳む）と同じ理由。

## 3. クリックの行き先

**「ブラウザが表示できるか」が判断基準。** 表示できない型はタブに送っても view にならず、
警告も選択肢もなくダウンロードが始まる。そこはペインに送る — 描画はできないが、ファイル名を
出して「OS で開く」を差し出せる。

画像・PDF・メディアは今までどおりタブ（issue の指定どおり）。

### 表を `common/` に出した

サーバは同じ表から `Content-Type` を決めている。**両側が同じ問いに答える**ので
`common/rawContentType.ts` へ移した。写しが 2 つあると、クリックをタブに送ったのに
サーバがそれをダウンロードにする、という形で食い違う。

移動は挙動保存の主張なので**差分ハーネスで証明した**: 拡張子・basename・ディレクトリ・
大文字小文字・サイズを組み合わせた **20,608 件で不一致 0**。壊すと 19,124 件検出できることも
確認済み。ハーネスは消し、**生成器と性質**を `test/common/rawContentType.spec.ts` に残した。

## 既存 spec が 2 件変わる

どちらも「今日はタブでダウンロードされる」ものをペインに寄せる変更で、意図したもの:

- `Makefile` / `archive.bin` を raw ルートに送る → ペインへ。`Makefile` はテキストなので
  そのまま表示される（クリックして期待する挙動になる）。
- `archive.zip` をペインに渡さない → 渡す。空のエディタではなく面が出るようになったため。

## 検証

- 実ブラウザで通し: xlsx をクリック → 面 → 「Open in OS」→ `open <file>`（実 argv を記録）。
- ルートの spec: 200 / 400（ディレクトリ・相対・引数なし）/ 403 / 404 / 500。
- `yarn format` → `lint` → `typecheck` → `build` → `test`。
