# feat: コレクションを見たまま、下のターミナルでチャットを進める (#2001)

## 問題

コレクションのカードやテンプレートからチャットを起動すると、`startCollectionChat` →
`placeSpawnedChat` がセッションをグリッドセルとして置き、`/terminals` へ移る。読んでいた
コレクションはその場で閉じる。「コレクションを見ながら、その内容についてエージェントに少し
手を動かしてもらう」が、毎回**画面ごと**切り替わる。

## 制約（実コードで確認済み）

- 配置は `registerSpawnedChatHandler` という**登録式の seam**。ただし `handlerQueue` は
  **ハンドラを 1 つしか持たない**ので、ここに登録すると GridView のものが外れ、外れたままになる
  （グリッドの登録は activate 時）。→ **同じ seam には登録しない**。
- サーバは **1 セッション 1 ソケット**。新しい attach は前のソケットに `superseded` を送って閉じる
  （`server/session/pty-connection.ts:103-111`）。クライアントは superseded の後、意図的に自動
  再接続しない（`reconnectPolicy.ts`）。→ **ペインとセルで同時に生かすことはできない**。

## 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| 所有 | ペインは**一時的な預かり所**。所有は分けない | 1 セッション 1 ソケットなので「2 つの生きたビュー」は作れない |
| 紐づけ先（**改訂**） | オーバーレイではなく、**コレクション**（`project\|kind:slug`、index も 1 つの場所） | 実際に使うと、オーバーレイに紐づける形は 2 つとも壊れていた: ①別のコレクションに移ってもペインが開きっぱなし ②グリッドに行って戻ると消えている。チャットはそのコレクション**について**のものなので、そこに file する |
| オーバーレイを閉じたとき（**改訂**） | **何もしない**（file されたまま残る） | これが②の直接の原因だった。グリッドへ渡すのは「Move to the grid」を押したときだけ |
| 復帰 | セッション id で durable slot（`persistKey`）を張る | 戻ってきたときに再接続して描き直すのではなく、**離れたときの端末がそのまま**出る |
| 受け渡し（改訂 4 で**廃止**） | 手放すのは「Move to the grid」を押したときだけ。そのとき **同じ request を `placeSpawnedChat` に渡す** | 走っているエージェントを画面の無い状態にしない。**閉じただけでは渡さない**（渡していたのが②の原因）。2 本目でも渡さない — タブとして並べる（改訂 2） |
| seam | grid の seam の**手前**に別の claim を置く | 上記のとおり同じ seam に登録すると grid の登録を外してしまう。claim が無ければ従来どおりの経路 |
| 同時に複数（**改訂 2**） | 1 コレクションに**複数**持てる。2 本目以降は**タブ**として並ぶ | 1 本目が動いている最中に次を訊くのは普通の使い方で、そのたびにグリッドへ追い出すのは代償が大きい。タブなら両方とも端末を保つ |
| タブの名前 | エージェント名（同じエージェントが 2 本以上なら連番）。tooltip にセッション id | 「Claude 1 / Claude 2」が一目で区別でき、id は引用したいときだけ読めばよい |
| タブを閉じる | 専用の × は置かない。「Move to the grid」が**見ているタブ**に効く | セッションは生きているので、閉じる＝どこかへ移すこと。破壊的な終了はセルの機能に任せる |
| 可視性（**改訂 3**） | ツールバーの **Collections のドアにセッション数のバッジ**を出す | ペインのチャットはグリッドセルではないので、他の画面からは存在が見えない。それが「グリッドに置かない」ことの代償で、置き場所の入口に数を出すのが最小の対処。通知ベルの未読バッジと同じ表現 |
| 位置 | **下**。高さはドラッグで可変、localStorage に保存 | コレクションのカードは横幅を食う。既存のスプリッタ幾何（`splitterWidth.ts`）に 5 本目として乗せる |
| 見た目 | 薄いヘッダー（エージェント名 + 「グリッドへ」）+ `hideHeader` の Terminal | 「簡素な terminal」。セルのクローム一式は要らない |
| ボタン | 閉じる（×）ではなく「**グリッドへ**」 | セッションは生きている。閉じるとしたら行き先はグリッドしかないので、そう書く方が正直 |

## 検証（改訂 3 まで。最終形は下の「改訂 4」— ここは経緯）

ユニットに加えて、**実際に動かして確認する**（CLAUDE.md の「blast radius が広い変更」）。

改訂前は「オーバーレイを閉じたらグリッドへ渡す」だったので、Grid view のあと**グリッドに
セルが 1 つ**あるのが正解だった。**改訂後は渡さないので 0 が正解**。以下は改訂後の期待値。

1. Collections → 「+ Collection」→ テンプレートカードを押す →
   **route は `/collections` のまま、オーバーレイも開いたまま、下にペインが出て Claude が動く**
2. index でチャットを起動 → ペインに出る

4. **Collections へ戻る → 同じセッションが戻る**
5. **Grid view へ → グリッドの端末は 0**（渡していない）
6. **Collections へ戻る → まだそこにある**（スクロールバックごと）
7. 1 本目 → **タブ 1 つ**。2 本目 → **タブ 2 つ**（`Claude 1` / `Claude 2`）、新しい方が選択される
8. **タブ 1 を押す → 表示が切り替わる**（aria-selected も入れ替わる）
9. **「Move to the grid」を押したときだけ**グリッドにセルが増え、そのタブが消える
10. チャットが無いときドアは素のまま、2 本走らせるとドアに **2** が出て、**グリッドに移っても見えている**
11. 実際の hook（`UserPromptSubmit` / `Notification`）で、タブのドットが **working** /
    **amber「waiting on you」**になり、要約行が出て選択タブに追従する
12. 自然に終了したセッションのタブはその場で消え、**ペインが画面に無い間に kill したもの**も
    戻ったときには消えている
13. console エラー 0

## 改訂 4 — セルとペインで「同じ端末」を共有する

> ユーザー: 「grid view と collection での session view は同じセッションを、grid view を開いている
> ときはそちらで、コレクション view を開いているときはコレクション内の session view で操作する
> ことは難しいでしょうか？ …Move to the grid のボタンを押さなくても、表示している view によって
> 切り替わればいいのかなと思いました。」

### できる。しかも受け渡しモデルより素直になる

「1 セッション 1 ソケット」は **ソケットを 2 本張る場合**の制約であって、この案には効かない。
`useTerminalConnections` の durable slot は再接続ではなく **DOM の付け替え**で、拡大セルを
Teleport で `.zoom-main` へ動かしているのと同じ仕組み（`docs/grid-view-modes.md` の事実 1）。
セッションを **1 つのグリッドセル**として持ち、コレクションを開いている間だけその
`TerminalCell` を **ペインへ Teleport する**なら、コンポーネントは再マウントされず、ソケットも
xterm もスクロールバックも 1 つのまま、置き場所だけが変わる。supersede は起き得ない。

### 決めたこと（改訂 4）

| 論点 | 決定 | 理由 |
|---|---|---|
| セッションの持ち主 | **常にグリッドセル**。起動時に `placeSpawnedChat` で置く（ただし**画面は移さない**） | 「grid view でも操作できる」を満たす唯一の形。オーバーレイの下でグリッドは生き続けている（`App.vue`: `<GridView />` の上にオーバーレイ） |
| ペインが見せるもの | そのセルを **Teleport で受け取る**。ペイン自身は端末を持たない | 再マウント無し = 再接続無し。ズームと同じ経路 |
| どちらが操作するか | オーバーレイが開いている間はペイン、閉じれば元のタイルへ戻る | オーバーレイはグリッドを完全に覆うので、裏のタイルが空でも見えない |
| Move to the grid | **廃止**。セッションは最初からグリッドに居る | ボタンを押さずに切り替わる、が要望 |
| タブ | そのコレクションに属する**セル**の切り替え。属する集合は従来の filing（`collectionChatKey`） | 改訂 2 のタブはそのまま活きる |
| ページ外のセル | 掴まれているセルは **`displayCells` に必ず含める** | 非ズーム時は現在ページの ≤9 しか描画されない（事実 3）ので、他ページのチャットが Teleport できない |
| グリッドが満杯のとき | file しない（従来どおりセッションは待機） | タブがあるのに実体が無い状態を作らない |
| 終了の検知 | 改訂 3 の仕組みをそのまま（`closed` push + `/api/sessions/live` 照合） | セルをグリッド側で閉じた場合もタブが畳まれる |
| 消えるもの | `collectionChatPane.ts`（配置の claim）、`collection-chat-<id>` の slot、「Move to the grid」 | 端末をペインが所有しなくなるので、まるごと不要 |

### 検証（改訂 4）— 実機で確認済み

専用の `HOME` / ワークスペース / ポート 34599 でサーバを起動し、Playwright で。**同じ DOM ノードが
移動していること**を、事前に押した目印（`data-probe`）で確認した（再接続や再マウントなら目印ごと
作り直される）:

| | 期待 | 結果 |
|---|---|---|
| 1 | コレクションから起動 → route は `/collections` のまま、端末はペインの中 | `inPane: [t0]`, `inGrid: []`, 端末は 1 つ |
| 2 | Grid view → **同じ** 端末がグリッドの中 | `inPane: []`, `inGrid: [t0]` |
| 3 | Collections へ戻る → また同じ端末がペインに | `inPane: [t0]`, `inGrid: []` |
| 4 | 2 本目 → タブ 2 つ、新しい方がペイン、1 本目はグリッドで動き続ける | `inPane: [t1]`, `inGrid: [t0]` |
| 5 | タブ 1 を押す → 入れ替わる | `inPane: [t0]`, `inGrid: [t1]` |
| 6 | Grid view → 両方ともグリッドに | `inGrid: [t0, t1]` |
| 7 | console エラー | 0 |

2 ページ目のケースも実機で確認した（CodeRabbit の指摘で追加）: shell を 9 本立ててチャットを
10 本目（= 2 ページ目）にし、**グリッドをページ 1 に戻した状態**で Collections を開く →
端末は 10 個マウントされ、ページ 1 の 9 本はグリッド、チャット（同じ目印 `t0`）はペインの中。
`cellsToDisplay` が掴まれたセルを描画しなければ、ここでチャットは消える。

### リロード（改訂 5）

改訂 4 の時点では、リロードするとコレクションの下のチャットが消えていた（filing がモジュール
状態だったため。セル自体はグリッドに残る）。実際に使って報告があったので永続化した:

- `collectionChatStorage.ts`（純関数）— localStorage `mt-collection-chats` の読み書き。壊れた
  エントリ・id の無いチャット・存在しない `activeId` は落とす。グリッドのレイアウトと同じ
  **ブラウザ状態**として持つ（そこに書いてあるのは、そのブラウザのセルだから）。
- 復元しただけでは監視が張られていないので、モジュール末尾で `listenForEndings()` と
  `scheduleSettleCheck()` を起動する。
- **セルの無いチャットは畳む**（`retireCellless`）。ペインは端末を持たず借りているので、セルが
  無いタブは空のペインの上に乗るだけ。グリッドが「まだ何も言っていない」状態（null）と
  「1 つも無い」（空配列）は区別する。

実機: 起動 → **F5** → route は `/collections` のまま、タブも端末も戻る（同じセッション id）→
Grid view → 戻る、まで確認。さらに「セルの無い filing」を localStorage に仕込んで読み込むと、
タブは出ず、保存も `{}` に掃除される。console エラー 0。

### 実機で見つけた回帰（改訂 5b）

コレクションを一度でも開いたあと、そのチャットのセルを**グリッドで拡大すると端末が消える**。
main では起きない。原因は Vue の Teleport:

> `to` が **disabled のまま**変わると、Teleport は古いターゲットを持ち続ける。あとで enabled に
> なった時点で、すでに DOM から外れたノードへ子を移してしまい、以後どこにも出てこない。

ペイン ↔ グリッドの往復で `to` が（disabled の間に）変わるので、その後の拡大が壊れていた。
**`v-for` の key に置き場所を混ぜて**、コレクションへの往復だけ別の Teleport にする
（`teleportKey`）。タイル ↔ ズームは同じ key のままなので、FLIP アニメーションが測った要素が
そのまま動く。key が変わるとセルは再マウントされるが、**端末は durable slot なので生き残る**
（`attach` が同じ xterm を付け替えるだけ）— 実機で、目印を押した同じ DOM ノードが往復することを
確認済み。

切り分けの経緯: `disabled` の式を main と同じに戻しても、`displayCells` を main と同じにしても
再現。ペインを**マウントしない**ようにすると直ったので、原因はペインの存在（＝ `to` の変化）だと
分かった。
